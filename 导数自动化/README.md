# 导数自动化

> 2026-10-27 立项。目标：把每期 35 个报告文件的导出从「手工点 50 多次」压到「一键」。
> 现状：**接口层已写好，等你开通紫鸟 WebDriver 权限后做连通性自检**。

---

## 一、为什么走紫鸟

你的账号都在紫鸟浏览器里，登录、验证码、IP 环境隔离紫鸟已经处理好了。
紫鸟客户端切到 **web_driver 模式**后会在本地开一个 HTTP 接口，
`startBrowser` 会返回这个店铺窗口的 `debuggingPort`，
Playwright 用 `connect_over_cdp` 直接接管**已经登录好**的窗口。

所以我们不碰登录，只点页面、点下载。这比另开一个浏览器去自动化安全得多，也不会触发风控。

| 对比 | 紫鸟 webdriver | 自建 Playwright |
|---|---|---|
| 登录/验证码 | 紫鸟负责 | 要自己处理，做不到无人值守 |
| IP 环境 | 紫鸟的环境，和平时一致 | 本机 IP，容易被风控 |
| 稳定性 | 官方接口 | 页面改版就失效 |

## 二、你要先做的一件事：开通 WebDriver 权限

**这一步只有你能做**，而且**必须用 BOSS 主账号**操作（子账号开不了）。官方文档：
https://open.ziniao.com/docSupport?docId=99

1. **进开发者控制台**
   打开紫鸟浏览器客户端 → 左侧导航栏点【开放平台】→ 首页点【开发者控制台】（免二次登录）
2. **开启 Webdriver**
   控制台首页找到「自动化 / 通讯录同步」区域 → **Webdriver 设置** → 点「开启 Webdriver 状态」
   （如果提示未绑定紫鸟企业账号，按提示先绑定）
3. **建一个专用自动化账号**（强烈建议，别用主账号跑脚本）
   企业管理 → 所有成员 → 【添加成员】，例如叫 `自动化_Robot`
   → 用这个账号登录一次紫鸟客户端，确认能登上
4. **确认角色权限**
   企业管理 → 角色管理 → 确认该账号的角色有 **「查看账号」** 权限（没有就加上）

做完后，把 `config.example.json` 复制成 `config.json`，填：

| 字段 | 填什么 |
|---|---|
| `company` | 登录紫鸟时输入的**企业公司名** |
| `username` | 自动化账号的用户名 |
| `password` | 自动化账号的密码 |

> ⚠️ `config.json` 里是明文密码，**不要提交 SVN**。
> 跑脚本时紫鸟客户端会被重启成 web_driver 模式，跑完用正常方式打开即可。

## 三、自检（我跑，你也可以自己跑）

```bash
# 1) 先看能不能连上、能列出几个店铺
python 导数自动化/ziniao_api.py --kill

# 2) 再验证「启动店铺 → 接管窗口」这条链路通不通
python 导数自动化/ziniao_api.py --kill --open <browserOauth>
```

`--kill` 会先关掉当前紫鸟客户端再以 web_driver 模式重启——**普通模式不响应接口调用**，
所以第一次必须带这个参数。之后如果客户端已经是 web_driver 模式，可以不带。

预期输出：

```
共 N 个店铺：
  亚马逊-美国主账号        siteId=1    oauth=xxxxxxxx
  亚马逊-interflow         siteId=1    oauth=yyyyyyyy
  ...
店铺已启动  debuggingPort=xxxxx  downloadPath=...
  当前页： 亚马逊卖家平台 | https://sellercentral.amazon.com/...
```

能打印出店铺列表 + 当前页标题，就说明整条链路通了。

## 四、接下来的实施顺序（按平台一个个来）

| 阶段 | 内容 | 报告数 | 说明 |
|---|---|---|---|
| **1** | 亚马逊管理库存报告 | 15 | 主账号 10 站点 + interflow 5 站点。跑批最核心的输入 |
| **2** | 亚马逊订单报告 | 12 | 主账号 8 站点 + interflow 4 站点 |
| **3** | 美客多 + EMAG | 6 | 美客多 Full 库存 + 订单；EMAG 库存 + 订单（会分页，已有合并脚本） |
| **4** | 库龄报告 | 16 | 亚马逊 10 + interflow 4 + 美客多 1 + EMAG 1 |

每个阶段都走同一个流程：

```
紫鸟启动店铺 → 接管窗口 → 进报告页 → 设筛选条件 → 点下载
  → 等文件落盘 → 按站点重命名 → 移到 快照日期/<YYYYMMDD>/
  → 跑 Daily_Sales_Report/pipeline/run.py
```

**关键设计**：下载路径由紫鸟的 `downloadPath` 决定，`notPromptForDownload=1`
已设成「不弹保存对话框」，所以文件会直接落地，脚本可以盯着目录等它出现。

## 五、一个已知的技术难点（已想好对策）

`管理库存报告` 的 26 列里**没有站点字段**（只有日本站是日文表头能认出来）。
所以不能靠文件内容判断是美国还是加拿大——**必须在下载的那一刻就知道是哪个站点**。

对策：脚本按「店铺 → 站点 → 下载」的顺序逐个执行，下载完成后立刻把文件
重命名成 `亚马逊<站点>管理库存报告<YYYYMMDD>.csv` 再移走。
不依赖内容识别，不依赖下载文件名。

## 六、和现有流程的关系

- `Daily_Sales_Report/pipeline/run.py` **不动**。它只认快照目录里的标准文件名，
  本目录做的是「把文件按标准名字放进快照目录」这件事。
- 跑批、体检、缺货表、库龄表、归档全部照旧。
- 如果自动化失败，手工导出 + 手工放进去，跑批一样能跑——**旧流程随时可回退**。
