# daily_update —— 日销表程序化每日更新

## 这套代码做什么

用当天导出的库存/订单报告，程序化完成日销表的手工三步：
1. **库存 sheet 替换**（可售/在途库存的值区，公式列不动）
2. **库存记录右移加列**（表头四件套 + VLOOKUP 公式列 + 样式复制，与手工一致）
3. **每日销售数据 append**（按 order-item-id 去重，辅助列公式平移，autoFilter 扩展）

保存后自动做 **zip 级保真回填**（customXml / 缩略图 / printerSettings / pivotCache refreshOnLoad）。

## 用法（每天）

```bash
cd Daily_Sales_Report\daily_update

# 看计划（不动文件）
python runner.py --dry-run

# 只跑指定工作簿（名字包含匹配）
python runner.py --only 日本,澳大利亚

# 全量
python runner.py
```

- 快照目录**自动选** `trunk\data\数据归属周期\202610\快照日期\` 下最新的 YYYYMMDD 目录；
  `--snap <目录>` 可手工指定。每天导哪些报告、放哪里，见《每日导数清单-2026年10月.md》。
- 缺某份报告 → 该项自动跳过并提示 `[缺报告]`，其余照常，不中断。
- 库存报告入库后自动把**锚点格**（模拟透视件的"下载日期"格，config.ANCHORS）滚动为快照日——
  透视图"上月/当月"分组跟着更新。
- 跑前自动备份到 `.workbuddy\backup_daily_YYYYMMDD\`。

## 换月（month_rollover.py，月底/月初跑一次）

9月归档 + 10月开新，窗口口径【上月7天 + 当月 + 下月1天】（促销期备案见清单文档第七节）：

```bash
python month_rollover.py --dry-run   # 先看变更计划
python month_rollover.py --apply     # 备份→采基线→归档→开新→校验
python month_rollover.py --apply --phase archive   # 只跑某一阶段
```

动作（对照 2026年8月 人工归档件逐格核实）：
- **归档版** → `2026年每日数据\{月}\{月}-原文件名.xlsx`：销售数据裁到 ≤下月1日；
  库存记录/每日库存分析表删 >下月1日 的尾列（只删尾部连续段，孤立日期格不动）；
  锚点格定格下月1日 + 透视图公式 `DAY(TODAY格±尾巴)` 重定向为 `DAY(锚点格±尾巴)`；
  真透视表件（欧盟/北美/Int北美）公式零改动；`=TODAY()` 保留。
- **10月版**（根目录原地）：销售数据删到只剩上月7天起（如 10月版保留 ≥9-24）；
  **删行后按新旧行号映射用 Translator 平移公式列**（delete_rows 不改公式引用，必须平移）；
  记录/分析表列不动（左侧删列会破坏跨表引用）。
- 校验：归档版 9月销量 vs 换月前基线（逐份必须一致）；记录列尾；锚点值；10月版窗口下限。
- 10-09 已跑通 9月→10月：10/10 销量与基线一致、公式平移抽查 0 差异、zip 完整性 OK。

换月前要改 `month_rollover.py` 顶部常量（ARCH_HI / OCT_LO / ANCHOR_D / ARCHIVE_DIR / ARCH_PREFIX / SEP_PROG），步骤见清单文档第六节。

## 配置（config.py）

- `latest_snapshot()`：快照目录自动发现；报告文件名模板 `{d}`=YYYYMMDD、`{d4}`=MMDD、`{m}`=订单月。
- `ANCHORS`：锚点格（runner 每天滚动 / 换月定格，两处共用；欧盟/北美的共享格带
  `stock_skipped` 门控——全部报告入库才滚）。
- `report`：可以是**单个模板**，也可以是**候选列表**（按顺序取第一个存在的）——亚马逊有的报告
  下载名不带日期（如 `欧洲多国库存.csv`），有的带（需你改名，如 `欧洲库存{d4}.csv` 放 DSR 根）。
- 报告格式 `kind`：
  - `inv`：管理库存报告（26 列 afn-*；日文界面导出的 24 列加 `colmap="JP24"` 按位置映射）
  - `age`：库龄库存报告（欧洲库存1006.csv 这种 90 列，字段名自动映射，researching 等缺失字段置 0）
  - `balance`：结余式"可售库存"sheet（FNSKU/ASIN/MSKU/Disposition/期末仓库余额）
  - `multi`：**整块重贴**（欧盟「多国库存」sheet ← 亚马逊「多国库存报告」，列名同名、行数随报告增减；
    多退少补、autoFilter 跟随末行）
  - 存量修复：`fix_id_text`（订单号 int→文本）每天幂等跑，无需配置。

## 已知边界

- 美客多（ml_full，10-12）/ 罗马尼亚 eMAG（emag_stock，10-13）/ 欧盟多国库存（multi，10-13）：
  xlsx/特殊报告已接入（换月归档时仍原样复制/保留）
- **锚点**：`config.ANCHORS` 内的"下载日期"格由 runner 每日滚到快照日（**必须列全该簿所有
  带日期的库存 sheet**——2026-10-12 曾因每簿只登记一个，「在途库存!C1」系列 4 个簿停在
  09-18、Int澳 B1 停在 09-14）。欧盟 `数据透视表!B11`、北美 `数据透视图!H5` 是**共享格**
  （各库存 sheet 的 C1 公式指向它），10-13 已登记 + `stock_skipped` 门控：**该簿全部库存
  报告都入库才滚动**，缺报告就不动（避免下载日期虚报新鲜度）
- **库存记录（10-13 起按天写固化值）**：新列 = 当天报告的冻结数值，不再是"复制上一列"的
  假公式；历史列不会被跑批静默刷新。手术在 openpyxl 保存后做 ZIP 级 XML 处理
  （`record_extend.extend_record_file`），中间无报告日只插表头、数据区留空；
  当天源报告缺失 → 该表不加列（下次报告到位从最后日期列一次性补齐）。详见
  《库存记录-在售块补到1012-改造报告-20261013.md》§六
- 分析表（货件四件套）与透视图重算：程序未覆盖，见缺口清单
