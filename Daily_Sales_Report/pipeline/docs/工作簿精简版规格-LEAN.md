# 日销表精简版（Lean）—— 设计规格

> 目标：把 12 份「库存销售表」从"公式驱动的重工作簿"改成**只留数据 + 程序算**的轻量版，
> 体积大幅下降、每天一条命令跑完，口径与 8/9 月手工版逐格一致。
> 依据：`.workbuddy/struct2.txt`（逐 sheet 实测范围）、`formula_inventory.txt`（公式清单）、
> `日销表工作簿结构档案-2026年8月-程序化复刻规格.md`。

## 一、为什么能瘦下来（实测）

| 元凶 | 实例（EU 簿） | 说明 |
|---|---|---|
| 明细表辅助列公式 | `每日销售数据` 20,304 行 × 3 列公式 = **60,908** 个公式格，部件 33.45 MB | AP/AQ/AR 等辅助列 |
| 分析表矩阵公式 | 英国/欧洲分析表 各 25,326 格；10 国镜像表各 23,962 格 | 日窗 SUMIFS + SUBTOTAL |
| 库存记录空列公式 | `美国预留库存记录` 42,249 格（真实数据只 651 行×67 列） | 300 列声明 vs 67 列有值 |
| 透视缓存 | `pivotCacheRecords1.xml` 10.69 MB | 真透视表 |
| 空壳单元格 | `多国库存` 11,992 个空壳 | 只有 1 个公式 |

**结论**：瘦身的本质 = **把公式算成值**（或直接删掉不再需要的公式列），
并删掉"只为了算而存在"的部件（透视缓存 / 空壳 / 无值列）。

## 二、保留 / 删除 总则

### 保留（业务要看的）
- **每日销售数据**：原始订单字段（amazon-order-id … order-item-id）+ **算好的**辅助列值（purchase date / 有效性 / 地区）
- **库存 sheet**（可售+在途 / 可售库存 / 在途库存）：报告字段值 + 算好的加工列（在途合计 / 现货）
- **库存记录**：SKU × 日期矩阵的真实快照值（行1 合计值化）
- **每日库存分析表**：SKU 行 + 货件列 + 算好的 F/G/H/AC/AD/AE/AF/AG/AH + 日窗销量值
- **订单数据 / 库存明细**（美客多、罗马尼亚）：原样保留数据 + 算好的辅助列
- **产品类型**、`Sheet1`、`2025年亚马逊有问题SKU号`：小表，原样保留

### 删除（用户已确认）
1. **透视表/透视图 sheet**：`数据透视表`/`数据透视图`/`数据透视图阿联酋`/`沙特透视图`/`新品销售情况数据透视图`/`墨西哥透视图`/`罗马尼亚透视图` → 汇总改由程序算（或保留一张轻量"汇总"sheet）
2. **明细表用不到的列**：商品长名、买家信息、发票、url、gift-wrap、promotion、is-business-order 等 → 只留算销量/库存必需的
3. **零值/空壳**：清掉只占位的空单元格，压缩 dimension

## 三、逐 sheet 保留列（明细表）

### 亚马逊订单报告（欧洲/北美/日本/沙特/澳/印/阿联酋/Interflowd×3）
原 33~44 列 → 保留 **14 列**：

| 保留 | 原列名 | 用途 |
|---|---|---|
| A | amazon-order-id | 单号 |
| B | merchant-order-id | TEMU 判定（北美） |
| C | purchase-date | 下单时间 |
| D | order-status | 取消判定 |
| E | sales-channel | 渠道/地区 |
| F | sku | 销量归属 |
| G | asin | 商品 |
| H | quantity | 件数 |
| I | item-price | 金额 |
| J | ship-country | 国家（辅助） |
| K | order-item-id | 去重键 |
| L | purchase date（算好值） | 归属日 |
| M | 有效性（算好值） | 口径闸门 |
| N | 地区/型号（算好值） | 分组 |

> ⚠️ 分析表的日窗公式引用 `每日销售数据!$L:$L`（SKU）、`$AP:$AP`（下单日）、
> `$AQ:$AQ`（有效性）、`$G:$G`（渠道）→ **瘦身后列位变化，分析表必须改成值**，
> 不能再留 SUMIFS（否则列位一挪就错）。

## 四、关键决策：分析表怎么算

分析表原有公式分两类：
1. **日窗销量**（AI…BU / AS…CE / I…AT）：`SUMIFS(每日销售数据!O, L=SKU, AP=日期, AQ=有效性, AR=地区)`
   → 程序按 (SKU, 日期, 有效性=1, 地区) 聚合 **每日销售数据** 直接写值。
2. **派生列**：F 可售=SUMIF(库存表 Y)、G 在途=VLOOKUP(AA)、H 调拨=Σ未到货货件、
   AC 差额=G−H、AD 实时速度、AE 上月日均（静态手填，保留原值）、AF/AG 天数、AH 月销=Σ当月日窗
   → 程序按同一语义重算成值。

**验证方式**：用 LibreOffice recalculate 出的工作簿当"标准答案"，逐格比对新生成的精简版
（数值必须完全一致；日期/文本同样比对）。
