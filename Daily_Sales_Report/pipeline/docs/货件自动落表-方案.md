## 2. 方案设计

新脚本 `Daily_Sales_Report\货件落表.py`（**独立跑，不动 runner**；以后想挂随时可挂）：

```
扫描 trunk\data\数据归属周期\*\货件\*.tsv（跨月份全扫，天然幂等）
 → 解析表头 + SKU 明细
 → 路由：目的仓 FC → 哪本簿·哪张表（FC 对照表内置；未知 FC 只报警不落表）
 → 方式判定（优先级从上到下）：
     ① 空运白名单（本次 7 件内置）
     ② 英国其余 → 卡航
     ③ 旧店 美国/加拿大 → 海运；新店 加拿大 → 海运；新店 其他 → 空运
     ④ 其余国家 → 默认空运（待你确认，见问题1）
     ⑤ 数量校验：空运量小、卡航量大，明显矛盾 → 提示人工复核（用法见问题4）
 → 找列：在该表第 1 行找货件号
     · 已有列 → 只刷新该列 SKU 数量（**不动日期/标签**，保护你手工改过的值）
     · 没有列 → 保留空列带里建新列：行1号 / 行2发货日 / 行3时效 / 行4到货 / 行5标签 / 行6合计 / 行7+SKU数量
 → 收尾报告：新建了哪些列 / 刷新了哪些 / 表里缺的 SKU / 方式矛盾件 / 保留带剩余列数
```

## 3. 保护措施
- 改簿前自动备份到 `backup_货件落表_<日期>\`（沿用现有备份习惯）；WPS 开着对应簿会拒绝写入并明确提示。
- 幂等重跑：同号只刷新数量，不重复加列。
- 保留空列带将满时预警，**不自动插列**（避免挤坏"在途差额"等公式区）。
- TSV 里有、表内没有的 SKU：只报告，不擅自加行。
