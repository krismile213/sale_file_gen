## 五、分析表计算列公式（以现行生产簿公式原文为准）

通用布局：r5 表头、r6 合计（=SUBTOTAL(9, 数据区)）、r7 起数据。列位因书种而异（2025-04 起标准位 E预留/F可售/G在途/H调拨合计/S差额…X月总；欧盟英国多国版右移，见《人工做表重要信息总档》大事记）。

### 5.1 罗马尼亚（eMAG；库存明细 c4=PNK c5=产品代码 c27=当前库存 c28=stock_type，A1=快照锚点）

| 列 | 公式原文（r7） | 说明 |
|---|---|---|
| E 预留库存 | `=SUMIFS(库存明细!$AA$5:$AA$29898,库存明细!$E$5:$E$29898,A:A,库存明细!$AB$5:$AB$29898,"In reception")` | 只统计 stock_type="In reception"；eMAG 报告只有 ready_to_sell/damaged → 恒 0（真 0） |
| F 可售库存 | `=SUMIFS(库存明细!$AA$5:$AA$29898,库存明细!$E$5:$E$29898,A:A)` | 当前库存合计 |
| G 在途库存 | 数组 `=SUMPRODUCT(--(ISNUMBER(SEARCH("到货",$I$5:$R$5))=FALSE)*NUMBERVALUE(I7:R7))` | I:R 货件列剔除表头含「到货」的列后求和 |
| H 调拨在途合计 | `=IF(ISNUMBER(FIND("到货",$I$5)),0,IF(I7="",0,I7))+…（J..R 同）` | 与 G 同语义的逐列写法 → **G=H，S 恒 0** |
| S 在途差额 | `=G7-H7` | |
| T 实时速度 | 全文见 §5.1.1①；要点：**= 当月累计 X ÷ (本月已过天数 − 当月缺货天数)**；月初已过<8天时分子改用窗内锚点前累计、分母=(已过+7−上月缺货−当月缺货)；兜底 **0** | 锚点=库存明细!A1；缺货天数来自透视图（§5.1.1①），活公式打开即算 |
| U 上月日均 | **无公式（手工静态列）** | 人工按上月销量÷30 估值（模板固有 ~32 行与 X 不齐，如填 0.1 =「日均不足 1 件」的估计）；程序 0 行改动原样继承 |
| V/W 在售(在途)可售天数 | `=(F7+E7)/T7`、`=(F7+E7+G7)/T7` | 分子含 **E 预留**（V），W 再加 **G 在途**；"在售"= 分母 T 已扣缺货天数（按有货在卖的天数平摊）；T 无效时显示 "-" |
| X 9月总销量 | `=SUMPRODUCT((MONTH($Y$5:$BK$5)=MONTH(库存明细!$A$1-1))*Y7:BK7)` | ⚠️ 公式语义 = **锚点前一日所在月的窗内累计**（当月 MTD，锚点走到月末时=当月全月）；表头「9月总销量」是上月遗留未改名。程序版按「快照月−1」取窗内上月部分 → 与公式语义分叉，见 §5.1.1③ |
| Y:BK 日销窗 | `=SUMIFS(订单数据!$H:$H,订单数据!$E:$E,$A7,订单数据!$AG:$AG,Y$5,订单数据!$AH:$AH,$D$4)` | H=数量、E=SKU、AG=购买日期、**AH=有效性(=1 才计)** |
| I:R 货件列 | **值（手工录入），表头 J:R 自动** `=TEXT(库存明细!$A$1,"M/D空运")` | I5 是静态文本；每票货一列，到货后表头补「到货」二字即从 G/H 中剔除 |

#### 5.1.1 速度/天数三列与 X 月份锚（2026-10-13 实测补全，对应「可售库存/在途/实时速度/上月日均/在售可售天数/在售在途可售天数」六字段提问）

**① T 实时速度全文**（生产簿与模板逐字符一致）：

```
=IFERROR(IF(DAY(库存明细!$A$1-1)<8,
   ROUND(SUMPRODUCT(($Y$5:$BK$5<库存明细!$A$1)*'罗马尼亚-每日库存分析表'!Y7:BK7)
        /(DAY(库存明细!$A$1-1)+7-SUMPRODUCT((罗马尼亚透视图!$B$8:$B$140=A7)*(罗马尼亚透视图!$E$8:$F$140))),1),
   ROUND(X7/(DAY(库存明细!$A$1-1)-SUMIF(罗马尼亚透视图!B:B,A7,罗马尼亚透视图!F:F)),1)),0)
```

- 月中分支（已过天数≥8，如 10-12 已过 11 天）：T = 当月累计 X ÷ (11 − 当月缺货天数) = **本月日均**
- 月初分支（已过<8天，如 10-06 已过 5 天）：本月样本太少 → 分子=窗内锚点前全部销量（≈上月末起 12 天），分母=(已过+7−[上月缺货+当月缺货])
- **缺货天数来源**：罗马尼亚透视图 B=型号、C/D=缺货起止时间，E=上月缺货天数、F=当月缺货天数（SWITCH 数组公式，把 [C,D] 区间与各月窗口求交；锚点同为库存明细!A1，公式里的 "−7" 边界与月初分支的 7 天滚动窗对应）
- 兜底：T 算不出 → **0**（V/W 是分母无效 → "-"，别混）

**② 六字段一句话速查**：

| 字段 | 含义 | 计算 |
|---|---|---|
| 可售库存 F | 手头能卖的件数（库存明细全状态合计） | SUMIFS(库存明细!AA, E, SKU) |
| 在途 G | 已发出未到架的件数 | I:R 货件列剔「到货」求和（大簿=取库存表 AA=P+Q+R） |
| 实时速度 T | 本月一天卖几件（按在售天数平摊） | X÷(已过天数−缺货)，月初切 ~12 天滚动窗 |
| 上月日均 U | 上月一天卖几件（人工估的参考值） | 手工静态列，无公式 |
| 在售可售天数 V | 手头库存按当前卖速撑几天（**含预留 E**） | (F+E)÷T |
| 在售在途可售天数 W | 连在途补货算上撑几天 | (F+E+G)÷T |

**③ ⚠️ X 月份锚：程序版与手工公式语义分叉（20261012 实锤，待拍板）**

- 手工/模板公式 `MONTH(库存明细!$A$1-1)`：A1=2026-10-12 → 月份=**10** → 活公式实算 = 10月累计（窗内 10/1~10/11）。历史佐证：2025-03 簿表头随月改为「3月总销量」、值=窗内 3 月部分——手工惯例是**表头跟随当月 + 公式算当月累计**
- 程序版（生成器 recompute_analysis，快照月−1 锚定）：10月簿写入的是**窗内 9 月部分**（9/24~9/30 共 7 天）
- 实测（程序版 output 日窗 9/24~11/1）：G381 程序写 1（=Σ9月窗内）；G433 模板公式实算=1（10月累计）而程序写 0 —— 跨月簿两口径必然分叉
- 连锁影响：程序版 T/V/W 保留公式，打开 Excel 后 T =「9月7天量 ÷ 本月已过天数」→ 与生产簿（本月日均）口径不一致，V/W 相应失真
- 生产簿表头当前仍挂「9月总销量」（未随月改名），若按表头字面理解会把 10月累计误当 9月总
- **待拍板**：X 跟公式语义（当月累计 + 表头改名跟随锚点月）还是跟表头字面（上月，需月末冻结值并同步改 T 公式）。拍板前，程序版 output 的 T/U/V/W 打开看到的值仅供参考

### 5.2 美客多（库存明细 c1..c33 ← Resumen 报告 c2..c34；F=库存明细!R 列可售）

与罗马尼亚同构，差异：
- E 预留 = SWITCH 数组公式：校验「ΣI:R 货件(剔到货) ≠ Σ库存明细!O:O」时走 SUMIF 分支（预留=在库未售部分）
  - ⚠️ **该分支实际是 `E = P + O − G`**（扣减项与 G 列公式逐字相同），即解恒等式 **E + G = P + O**。
    **G > P + O 时 E 必为负**——20261016 实测 O合计 1520 + P合计 4 = 1524，而货件列合计 G = 2777
    ⇒ 缺口 1253 件、**126 行** 预留为负（典型：O=0 而货件列>0，新票平台未登记）。
    根因是"货件列=PDF 入库准备单的计划发出量"与"库存明细 O=平台已确认在途"两源不同步。
    影响 `V 在售可售天数 =(F+E)/T`。修法：`MAX(0,…)` 防负 / 直接用 `=P` / 让货件列与平台对齐。
  - 另：SUMIF 范围 E 列用 `$C$5:$C$29896`、F 列用 `$C$5:$C$29893`，不一致且远超实际数据行（止于 r361），
    手工改过的痕迹（本例不影响结果）。
- F 可售 = `SUMIF(库存明细!$C$5:$C$29893,A:A,库存明细!$R$5:$R$29893)`
- 日销窗 = `SUMIFS(订单数据!$G:$G,订单数据!$S:$S,$A7,订单数据!$BL:$BL,Y$5,订单数据!$BM:$BM,$D$4)`（G=数量、S=SKU、BL=购买日期、**BM=有效性=1**）
- X = `SUMPRODUCT((MONTH($Y$5:$BK$5)=MONTH(库存明细!$A$1-1))*Y7:BK7)`（公式语义=当月累计；程序「快照月−1」分叉同 §5.1.1③）
- 订单数据的西语正典规范化（c64 purchase-date / c65 有效性公式依赖西语月名表/关键词表）：见 config.py L238-328

## 七、核对时的注意事项（易错点）

1. **分析表公式 vs 程序值化**：主仓库生产簿（1.每日销售数据表）分析表是**活公式**，openpyxl 读不到值（缓存 None），要用 Excel/WPS 打开才算；程序版 output（日销表程序版\output、会话区 output）的罗马尼亚/美客多分析表是**值化**的（recompute_analysis 写死），可直接读值核对。T/U/V/W（实时速度/日均/天数）在程序版保留公式、fullCalcOnLoad，程序不背书其值。
2. **日销窗四条件缺一不可**：SKU × 日期 × **有效性=1** × 站点（欧盟英国还有 sales-channel 筛选）。复算时漏筛有效性会每组多出 1~2 件（取消单/退货单）。
3. **G=H（罗马尼亚/美客多）是口径事实**：在途与调拨在途合计在无船司分区表里同源（I:R 剔到货），S=G−H 恒 0；欧盟英国线货件列更多（I:U + 欧洲区 V:AB），S 可非 0。
4. **I:R 货件列是全簿唯一手工值列**：每票货一列、表头「M/D 运输方式」、到货后表头补「到货」即自动从 G/H 剔除；程序不写这两区（罗马尼亚 J:R 表头随 A1 锚点滚动，但值仍手工）。
5. **月总列月份锚（⚠️ 有分叉，详见 §5.1.1③）**：模板公式语义 =「锚点前一日所在月」的窗内累计（当月 MTD）；程序版当前按「快照月−1」取窗内上月部分。欧盟英国公式锚 = 数据透视表!B11（同款 SUMPRODUCT）。跨月做表先滚动锚点；拍板前程序版 X/T/V/W 打开值仅供参考。
6. **AA「在途库存」列**是本地公式列（=P+Q+R），不在程序写值白名单里——新增 SKU 行由程序补公式，手工插行要自己拖公式。

## 九、每日销售量计算逻辑（三级结构，2026-10-15 补）

「每日销售量」不是一个公式，而是**三级流水**：订单报告先落进「每日销售数据」sheet（程序），分析表日销列用 SUMIFS **活公式**实时算（打开即算），月底再由程序按同口径重算写进月汇总封存列。三级口径必须一致，任何一级失守都会让月总数与日销窗对不上。

```
① 订单报告(txt/xlsx) ──runner.append_sales()──▶ 「每日销售数据/订单数据」sheet
                                              （原字段按列名映射 + 派生辅助列，组合键去重、窗口过滤）
② 分析表日销列 AI+ … ──SUMIFS 活公式──▶ 当日每 SKU 销量（Excel/WPS 打开即算，程序不写值）
③ 月汇总封存列 ──analysis.resolve_month_sales() 按等价口径重算写静态值──▶ 上月整月销量
```

### 9.1 第一级：订单行进表（`runner.append_sales`，runner.py L767）

| 步骤 | 规则 | 原因/备注 |
|---|---|---|
| 表头定位 | `_header_row` 找含 `order-item-id` 的行作为表头行 | 亚马逊系 r2 起数据；罗马尼亚/美客多 r1 有值 |
| **组合键去重** | `order-item-id` + `amazon-order-id` + `sku` + `purchase-date`(前19位) 四元组进 `have` 集合，报告里已存在的跳过 | **不能用纯 order-item-id**：MCF 多渠道配送单的 order-item-id 全是 `'0'`，纯 oid 去重会整批误杀。美客多按 `# de venta`、EMAG 按 `订单编号` 作 key |
| **窗口过滤** | `purchase-date` 前 10 位 < `WINDOW_LO` 的行整行丢弃（日志打「窗口外过滤N行」） | 月度订单报告按「最后更新日期」导出，会混入 2024/2025 退款散单、上月早期散单；挡住后才维持「上月 7 天 + 当月」窗口口径。`WINDOW_LO` = 上月最后一天 − 6 天（`config._window_lo`，202610 → 2026-09-24），随周期自动推导 |
| 列映射 | 按 sheet 表头名对报告列名写入；ID 类列（`TEXT_COLS`）保持文本，数值列 `_num()` 转换 | ID 长数字列保文本防科学计数法 |
| 辅助公式列平移 | 数据首行是公式的列（如 AE/AF、AP/AQ/AR），新行用 `Translator(f0, origin=首行).translate_formula(新行)` 平移；**ArrayFormula 单独分支**处理 | 漏判 ArrayFormula 会抄下指向旧行的错公式（见 §七 坑） |
| autoFilter | 扩展到最后一行 | |

### 9.2 第二级：分析表日销列 SUMIFS（活公式，打开即算）

**日本表实证**（20261015 读生产簿，`日本-每日库存分析表` BK7，四条件）：

```
=SUMIFS(每日销售数据!$O:$O, 每日销售数据!$L:$L,$A7, 每日销售数据!$AE:$AE,BK$5, 每日销售数据!$AF:$AF,$D$4)
```

**欧盟英国表实证**（`英国-每日库存分析表` BU7，**五条件**——多站点筛选）：

```
=SUMIFS(每日销售数据!$O:$O, 每日销售数据!$L:$L,$A7, 每日销售数据!$AP:$AP,BU$5, 每日销售数据!$AQ:$AQ,$D$4, 每日销售数据!$G:$G,$D$5)
```

条件分解（D4=1、D5=站点/地区，因簿而异）：

| 条件 | 列 | 含义 |
|---|---|---|
| 求和列 | O | quantity 数量 |
| ① SKU | L = `$A7` | 分析表 A 列 SKU |
| ② 日期 | AE=`=LEFT(C3,10)` / AP 同 | 购买日期取前 10 位 = 表头行5日期 `BK$5` |
| ③ 有效性 | AF/AQ = `=IF(AND(E3<>"Cancelled",MID(G3,1,7)="Amazon."),1,0)` | 必须 `=$D$4`(=1)：**非 Cancelled 且渠道是 Amazon.** |
| ④ 站点/地区 | G（欧盟英国专有） = `$D$5` | 英国表 D5=`Amazon.co.uk`；欧洲表 D5=`欧洲`，走派生列 `AR=IF(G3="Amazon.co.uk","英国","欧洲")`——**统计欧洲自动排除 co.uk**，否则高估约 1.8 倍 |

各簿日销列起点不同（日本 BK、欧盟英国 AI、罗马尼亚/美客多 Y），但五条件结构不变；缺任一条件复算时每组会多出 1~2 件（取消单/退货单）。

### 9.3 第三级：月汇总封存（`analysis.resolve_month_sales`，analysis.py L453）

日销 SUMIFS 是活公式，月底要把「当月整月销量」固化成静态值进月汇总区（每表两块 12 个月，第一块对月销表）。程序不重算 Excel 公式，而是**解析活公式反推口径、回到原始订单行按等价口径重算**：

1. `parse_daily_sumifs`（L340）从最新日销列公式反解出 spec：`{src, qty, sku, date, valid, extra}`（全是列字母），靠 `$A7`/`X$5`/`$D$4`/`$D$5` 四个锚点识别各条件列。
2. `scan_analysis`（L383）扫行5：日期列里最后一个 SUMIFS 列 = 最新日销列；`D4/D5` 取条件值；行5 `「N月」` 标签定位月汇总列。
3. `resolve_month_sales`（L453）read_only 流式扫源表，按 ym 过滤 + 有效性 + extra，累加每 SKU 销量。自动识别三类簿口径：
   - **amazon**：`E<>"Cancelled"` 且 `MID(G,1,7)="Amazon."`；北美系额外放行 B 列含 `TEMU`；
   - **emag**（罗马尼亚）：M 列不含 `Canceled`/`Storno` 子串；
   - **ml**（美客多）：透视图 K/L 关键词表三级兜底（XLOOKUP 精确 → LOOKUP 包含 → C 列再匹配），日期走西语文本解析（`31 de agosto de 2026`）。
4. **封存源 = 上月归档簿** `2026年每日数据/{M}月/{M}-原名.xlsx`——当前簿换月已裁剪，直读只会读到月尾残值（10-13 曾错封 1537/5524）。写入后 `freeze_month` 清当月列残留、`rename_current_header` 滚表头。
5. 20261014 全簿激活实测：9 月封存 欧 24981 / **英 6854** / 北美 4540·1542·1534 / 日 5101 / 沙 1425 / 澳 1611 / 印 1108 / 阿 966 / 美客多 1299 / 罗 138；「写入 < 重算」的差 = 分析表缺 SKU 行（补行后须重跑才能落数量，依赖 apply_sheet 的空格回填）。

### 9.4 口径红线（改任一级前先读）

1. **去重必须用组合键**，纯 order-item-id 会误杀 MCF 单。
2. **窗口过滤不能删**：月度报告按最后更新日期导出，不过滤会破坏「上月 7 天 + 当月」口径。
3. **日销 SUMIFS 五条件缺一不可**：SKU × 日期 × 有效性=1 × 站点（欧盟英国）；欧洲排除 co.uk。
4. **三级同口径**：月封存值必须与日销窗逐日累加对得上；对数用 `verify_ship_afn.py` 同思路的独立重算，别信缓存列（归档簿「当月总销量」缓存列已空=0）。
5. 程序只负责「值 + 公式平移」，**T/U/V/W（实时速度/上月日均/可售天数）是活公式，程序不背书其打开值**（fullCalcOnLoad，须 Excel/WPS 实算）。
