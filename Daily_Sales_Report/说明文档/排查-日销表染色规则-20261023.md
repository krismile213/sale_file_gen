## 三、澳大利亚「零销量标红」= 断货标记

按实际显示色统计（行 7-382 × 39 日列 = 14664 格）：

| 颜色 | 规则 | 格数 | 其中零值 |
|---|---|---|---|
| 浅粉 `FFFFDDE7` | prio 1236 断货 + **有在途/调拨** | 534 | **534** |
| 红 `FFFF0000` | prio 1232 低基数补偿 | 133 | 0 |
| 红 `FFFF0000` | prio 84 高倍数 | 19 | 0 |
| **玫红 `FFFF8FA8`** | prio 1235 断货 + **无在途无调拨** | 11 | **11** |
| 蓝 `FF61D8FF` | prio 85 低销量 | 10 | 0 |

**红色格子里没有一个是 0。** 用户看到的「零销量标红」是：

1. **玫红 `FFFF8FA8` = RGB(255,143,168)** —— 视觉上和红 `FFFF0000` 几乎分不开（11 格）
2. **浅粉 `FFFFDDE7`** —— 断货期标记，534 格，扫一眼就是「一片红」

### 粉色规则完整公式

```
prio 1235 (玫红):
  AND( $A7<>"", N($F7)<=0, SUM($Y7:$BK7)>0,
       锚点 - 1 - LOOKUP(2,1/($Y7:$BK7>0),$Y$5:$BK$5) >= 3,
       Y$5 > LOOKUP(2,1/($Y7:$BK7>0),$Y$5:$BK$5),
       Y$5 < 锚点,
       N($G7)=0, N($H7)=0 )        ← 在途=0 且 调拨在途=0

prio 1236 (浅粉):
  同上，末条换成 OR(N($G7)>0, N($H7)>0)
```

**关键：1235 与 1236 的区别是「有没有在途」，不是日期。**

### 判定链（为什么会标到未来日期）

`Y$5 < 锚点` 只要求「该日期早于锚点日」。锚点 = `新品销售情况数据透视图!$F$1`。
若锚点被设成快照日之后的日期，断货后的**未来日期**（BC..BK，值全 0）也会被一并标粉。
本次实测行 9（G487）从 BB(10-23) 一直标到 BK(11-01)，正是这个原因。

## 六、勘误与已实施（2026-10-23 二次核验）

### 勘误：「标到未来日期」是我的复算器漏判，不是表的问题

初版复算器 `hit()` 的粉色分支**漏了 `Y$5 < 锚点` 这个上界条件**，把锚点之后的未来日列
（BB..BK，值全 0）也算成命中，因此报出「行 9 从 10-23 标到 11-01」。

实测 16 张表的锚点全部 = **2026-10-23（快照日）**，规则 `Y$5 < 锚点` 数学上只覆盖到 10-22，
**Excel 里本来就不会标未来**。补上上界后重算，真实染色数：

| 表 | 修正前（误报） | 修正后（真实） |
|---|---|---|
| 澳大利亚 浅粉 | 534 | **253** |
| 澳大利亚 玫红 | 11 | **1** |
| 欧洲 玫红 / 浅粉 | 89 / 44 | **49 / 6** |
| 英国 玫红 / 浅粉 | 48 / 103 | **8 / 43** |

红色格子（`FFFF0000`）修正前后都是 **零值 0 个**，结论不变：
「零销量标红」看到的仍是玫红/浅粉断货标记。

### 已实施：加防御上界（用户 2026-10-23 拍板）

虽然现状已不标未来，仍按用户要求加了一道保险：

```
日列规则尾部  ,{L1}$5<{锚点}
        ↓
              ,{L1}$5<MIN({锚点},TODAY()+1)
```

- 锚点正常（= 快照日）→ `MIN` 取锚点 → **与原公式完全等价**，实测染色一格没变
- 锚点被误设成未来 → `MIN` 封顶到今天，不会标未来
- 打开历史归档时 `TODAY()` 变大 → `MIN` 仍取锚点 → 历史染色不受影响

**实现方式（重要）**：用 `patch_pink_ceiling_20261023.py` **直接改 sheet XML 里的公式字符串**，
不重写工作簿。原因：`openpyxl` 存盘会丢掉所有公式缓存值（日销列是 SUMIFS），
导致 `data_only` 读出来全是 None，归档副本/脚本预览会看到空表。
纯 XML 替换能保住缓存值、透视表缓存、富数据。

- 16/16 张表验证通过（每张正好 2 处替换）
