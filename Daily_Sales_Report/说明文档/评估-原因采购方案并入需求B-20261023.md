# 评估：详细版的「原因 / 采购方案」能否并入需求B

> 用户问：「详细版（原因分析 + 采购方案）的原因分析和采购方案 sheet 也可以加到需求B那吗？」
> 需求B = `断货分析/亚马逊/每日缺货/<日>/亚马逊美客多EMAG缺货情况表.xlsx`
> 详细版 = `断货分析/亚马逊/断货明细/<日>/断货明细_<日>.xlsx`

---

## 一、结论

**能并，但不能简单并。** 详细版是需求B 的**真子集**（603 行 100% 落在需求B 里），
但需求B 另有 **935 行没有原因/方案**，因为两边断货口径不同。

---

## 二、结构对比

两个文件都是「第 1 行标题说明 + 第 2 行表头 + 第 3 行起数据」。

### 详细版「采购建议」— 22 列

`地区 / 账号 / SKU / 品名 / 可售 / 在途 / 近7天 / 近30天 / 日均 / 可售天数 /`
`0-30 / 31-60 / 61-90 / 91-180 / 181-270 / 271-365 / 365+ / 呆滞>90天 /`
`优先级 / 状态 / **原因** / **采购方案**`

### 需求B「一级」— 15 列

`缺货等级 / 站点 / 账号 / SKU / 品名 / 可售库存 / 在途 / 近7天 / 近30天 / 日均 /`
`可售天数 / 计划备货天数 / 缺口天数 / 判定依据 / 数据源`

### 详细版独有、值得并进去的 5 列

| 列 | 内容示例 | 价值 |
|---|---|---|
| 状态 | 严重断货 / 一般断货 / 预备断货 | 与需求B 的一/二/三级是**另一套分级** |
| 原因 | 「可售 0 且在途 0」「近30天 0 销量，先确认是否下架」 | 直接可读的结论 |
| 采购方案 | 「建议补 X 件（14 天覆盖）」 | 可直接下单 |
| 优先级 | P0 / P1 / P2 / P3 | 排序用 |
| 呆滞>90天 | 件数 | 判断「该不该补」 |

需求B 独有、详细版没有的：`计划备货天数 / 缺口天数 / 判定依据 / 数据源`。

### 935 行的画像

- 可售 1~20 件，在途多为 0，缺口天数 8~47 天

**说明这 935 个 SKU 是真实在卖、真实缺货的，只是详细版不认为它们「断货」。**

## 四、为什么口径不同（关键）

| | 详细版 | 需求B |
|---|---|---|
| 判定依据 | **14 天覆盖**（后勤周期 7 天 + 目标覆盖 14 天） | **计划备货天数 60-120 天**（读 `备货天数.xlsx`） |
| 断货数量 | 622 个（严重 290 / 一般 287 / 预备 45） | 1520 个（一级 1071 / 二级 289 / 三级 292） |
| 数据源 | 库存报告 + 订单报告（自己算） | 12 本工作簿的分析表（公式值） |

**差集 935 行 = 14 天覆盖下还够卖、但按 60-120 天计划备货不足的慢销品。**

需求B 的一级定义就是「可售 > 0 但 可售天数 + 7 < 计划备货天数」——
对 60~120 天的计划备货来说，慢销品几乎必然命中，所以一级量特别大（1071 个）。

---

## 五、三个方案

### 方案 A（推荐）：左连接补 5 列

在需求B 每个 sheet 右侧追加：`状态 / 原因 / 采购方案 / 优先级 / 呆滞>90天`，
按 `(站点, SKU)` 左连接详细版。935 行填 `—（14 天覆盖下不判定货）`。

- 改动量：`shortage_report.py` 里加一段 join + 5 个列
- 优点：一张表看全，不动现有列
- 缺点：935 行看着"空"，需要图例说明；且两边数字可能不一致（不同数据源）

### 方案 B：原样附「采购建议」sheet

把详细版的「采购建议」sheet 整张附到需求B 文件末尾，两个口径并存。

- 改动量：最小（copy sheet）
- 优点：零口径风险，两套结论都能查
- 缺点：用户要在两个 sheet 之间对照，不是「一张表」

### 方案 C：统一口径后彻底合并

让详细版改用需求B 的 `plan_days` 重新判「断货」，两边变成同一件事，再合并。

- 改动量：最大（`stockout_report.build()` 的分级逻辑要重写）
- 优点：最干净，只有一套断货定义
- 缺点：会改变详细版现有的「严重/一般/预备」历史口径，需要重新对齐历史数据

---

## 六、建议

先做 **方案 A**，同时给 935 行标清楚"为什么不判定货"，让用户跑一周看是否够用；
如果用户实际更关心「按 60-120 天计划备货够不够」，那直接走 **方案 C**，
因为方案 A 里那 935 行空着，等于需求B 一半的行没有采购建议——这本身说明
「14 天覆盖」和「60-120 天计划备货」是两套目标，不该硬塞进一张表。

**需要用户拍板：采购补货的目标覆盖天数，到底是 14 天还是 60-120 天？**

### 影响（用户需知）

- **待补货件数从 150 → 9462 件**（20261023）。原因：补货目标覆盖天数从 14 天改成计划备货天数
  （欧洲/英国 120 天、美国 95、加拿大/阿联酋/沙特 75、日本/澳洲/罗马尼亚/美客多 60、印度 65）。
  判定说缺 120 天却只补 14 天会自相矛盾，所以同步对齐。
- **预备断货 45 → 1071**，这是需求B 一级本来就算的慢销品。
- `--no-plan` 可完整回退（实测 预备 45 / 待补货 165）。

### 遗留

- 两边**数据源**仍未统一（库存报告 vs 工作簿公式值），52 行等级差异是必然的。
  要彻底一致，得让需求B 也读库存报告，或让详细版也读工作簿 —— 工作量更大，本次未做。
