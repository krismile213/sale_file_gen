## ✅ 2026-10-16 定稿：无销量口径 =「(锚点格 − 1) − 最后销售日 ≥ 3」

> **用户原话**：「比如 1016 导的，要 1013-1015 3 天没有才行；1016 早上导数，就不算了」。

- **无销量天数**从「**最后一个有数据的日子**」（快照日 − 1 = **10/15**）起算，
  **快照日 10/16 当天不计入**（10/16 是早上导数的当天，数据未满）。
- 公式：`(锚点格 − 1) − 最后销售日 ≥ 3` ⇒ 最后销售日 ≤ **10/12** 才命中；
  「无销量天数」与日列**实际染色段长度严格相等**（如 10/13~10/15 = 3 天）。
- 文件里的 CF 条件④ 已改为 `{锚点}-1-LOOKUP(2,1/(日销列>0),日销行5)>=3`。
- 日列染色**上界仍用原始锚点**（`日头 < 10/16`）⇒ 染色段覆盖到 **10/15**（不因此少染一天）。

**命中数（最终）**：16 张共 **152 行**（深粉 **39** / 浅粉 **113**）。

> 曾被评估过的另一口径 A =「锚点格(10/16) − 最后销售日 ≥ 3」（命中 171）**已废弃**；
> 差异全在「最后销售日 = 10/13」那类行（A 命中、B 不命中）。

## 五、关于「日销列是 SUMIFS，要打开重算才显示粉标」

**问题成因**：分析表的 `F/G/H` 与 39 个日销列全部是公式，`openpyxl` 写盘时**不会写公式缓存值**，
所以刚生成的文件里这些格「看起来是空的」；条件格式的判定式依赖 `SUM(日销列)`、`F`、`G`、`H`，
Excel/WPS 重算后才会有值 → 粉标随之出现。

**已做的处理**：给全部 16 张簿（以及 `pipeline/core/runner.py` 日常落盘的每一张簿）
写入工作簿级属性：

```
wb.calculation.fullCalcOnLoad = True   → xl/workbook.xml 里 fullCalcOnLoad="1"
wb.calculation.calcMode = "auto"
```

**效果**：用 Excel / WPS 打开文件时**自动全量重算**，不需要手动按 F9，粉标即按上表出现。
本机**没有 Excel / WPS 主程序 / LibreOffice**（仅 `wpscloudsvr.exe`），也没有可用的公式求值库，
所以**无法在本地把缓存值写进文件**——这是唯一无法在服务器侧消除的一步；
`fullCalcOnLoad` 已经是这个前提下能给出的最优解（打开即算，无需人工干预）。

**对表方法**：打开文件后按上表逐条核对。若某条对不上，把 **SKU** 发我，我按该表公式立刻定位
（大概率是某张源表当天更新、或 `G` 在途源列公式形态变化）。
