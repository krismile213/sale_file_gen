# 日销表数据原理与计算方式 · 扫盲手册

> 适用范围：`sale_file_gen\Daily_Sales_Report\1.每日销售数据表\` 下的全部「库存销售表」工作簿。
> 写作依据：2026-10-08 对目录内 12 份工作簿、上级 `sale_file_gen\trunk\` 代码及既有文档的实际读取结果，
> 文中所有公式均为从表里原样抄出来的（注明所在 sheet），不是猜的。
> 读者假设：从零接触这套表的新人，要能看懂每一层"数字是怎么来的"。

---

## 0. 三句话看懂

1. **日销表 = 运营侧的每日盯盘工作簿**：每月每个国家/平台一份 xlsx，里面同时装着「订单明细 + 库存明细 + 每日库存快照 + 在途货件跟踪 + 销量透视」，数据靠"从平台后台下载报告 → 粘贴进对应 sheet"来喂。
2. **销量口径一句话**：`订单报告粘贴 → 辅助列打好有效性标记 → 数据透视表筛选"有效 + 归属月" → 对 quantity 求和`。按**下单日期**归属，剔除**取消单**。
3. **库存口径一句话**：`库存结余报告 → 每日粘贴一列（库存记录）`；`库存清单报告 → 在途三态（刚发/运输中/待接收）加总成"在途库存" → 每日库存分析表逐票货件跟踪到货`。

## 2. 工作簿解剖学：每一类 sheet 是干什么的

12 份工作簿按结构分**三种变体**。

### 2.1 变体 A：亚马逊多站点版（欧盟英国、北美加拿大、Interflowd北美加拿大）

| sheet 组 | 成员 | 内容 |
|---|---|---|
| 销售明细 | `每日销售数据` | 亚马逊 All Orders 订单报告原样粘贴（TSV 导出，表头在第 2 行）+ 辅助列 |
| 库存清单 | `{国家}可售+在途库存`（欧盟：英国/欧洲；北美：美国/加拿大/墨西哥×2） | FBA **库存清单报告**（afn-* 全字段）+ 加工列（见 §5） |
| 库存结余 | `美国`/`加拿大`/`墨西哥`（北美版独有） | FBA **结余报告**（FNSKU/ASIN/MSKU/Disposition/Ending Warehouse Balance） |
| 每日快照 | `{国家}库存记录` | SKU × 日期矩阵，**每天下载后粘贴当日一列**（见 §5.3） |
| 在途跟踪 | `{国家}-每日库存分析表` | SKU × 货件矩阵，逐票货件跟踪到货（见 §5.4） |
| 销量透视 | `数据透视表`/`数据透视图` | 筛"有效性=1 + 归属月"，按 sales-channel/地区求和 quantity（见 §4） |
| 辅助 | `多国库存`（欧盟独有） | Pan-EU 多国库存报告：`quantity-for-local-fulfillment`（本地履约量） |
| 辅助 | `2025年亚马逊有问题SKU号`（欧盟） | 按月记录有问题 SKU 的清单（SUBTOTAL 计数） |
| 辅助 | `Sheet1` | 空的，忽略 |

### 2.2 变体 B：亚马逊单站点版（日本、沙特、阿联酋、印度、澳大利亚 + Interflowd 澳/阿联酋）

与变体 A 的区别就一点：**"可售库存"和"在途库存"拆成两张 sheet**（单站点不需要按国家再拆）。

- `每日销售数据`（沙特/阿联酋版 sheet 名带站点后缀）
- `可售库存` ← FBA 结余报告（Disposition=SELLABLE 结存）
- `在途库存` ← FBA 库存清单报告（afn-*，含在途三态列）
- `{站点}-每日库存分析表`、透视图
- 印度版多一张 `亚马逊有问题SKU号`

### 2.3 变体 C：非亚马逊版（美客多、罗马尼亚=eMAG）

| sheet | 美客多（西语列名） | 罗马尼亚 eMAG（中文列名） |
|---|---|---|
| 订单明细 | `订单数据`：# de venta / Fecha de venta / Estado / Unidades / Ingresos... | `订单数据`：订单编号 / 订单日期 / 产品代码 / 数量 / 订单状态（Finished/Canceled...）/ 付款状态 |
| 库存明细 | `库存明细`：ML Full 仓库存（西语状态，见库存文档 §5） | `库存明细`：offer 级 stock / status / handling_time |
| 商品分类 | `产品类型`：IFS 公式自动分"新品/热销品/一般产品/滞销品/待停售产品" | 同左（两份文件这页一模一样） |
| 透视 | `墨西哥透视图` | `罗马尼亚透视图` |
| 在途跟踪 | `墨西哥-每日库存分析表` | `罗马尼亚-每日库存分析表` |

> `产品类型` 的分类公式（美客多/罗马尼亚共用，D 列）：
> `=IFS(C2="停售","待停售产品", VALUE(MID(A2,2,3))>199,"新品", B2>=20,"热销品", B2<5,"滞销品", AND(B2>=5,B2<20),"一般产品")`
> 即：商品资料状态=停售 → 待停售；**SKU 编号后三位 >199 → 新品**（SKU 编号大 = 后来上的品）；当月销量 ≥20 → 热销；<5 → 滞销；其余 → 一般。
> ⚠️ B 列表头写的是"10月销量"——这是从上期复制带来的静态表头，换月时要记得改，值也要重填。

## 3. 原始数据从哪来（报告清单）

日销表里所有"粘贴进来的数据"只有五种来源：

| 报告 | 后台位置 | 粘到哪个 sheet | 频率 |
|---|---|---|---|
| 亚马逊 All Orders 订单报告（TSV/txt） | 亚马逊后台 → 订单报告 | `每日销售数据` | 每日/数日 |
| FBA 库存清单报告（FBA Inventory，afn-*） | 库存报告页 | `在途库存` / `{国家}可售+在途库存` | 每次下载（大约每周+大促前后） |
| FBA 库存结余（Inventory Ledger 结余，Ending Warehouse Balance） | 库存报告页 | `可售库存` / `美国` 等 | 同上 |
| Pan-EU 多国库存报告（欧盟） | 欧洲站后台 | `多国库存` | 同上 |
| 美客多订单导出 / ML Full 库存；eMAG 订单导出 / offer 库存 | 各平台后台 | `订单数据` / `库存明细` | 每日/数日 |

> 下载后第一件事：把对应 sheet 第 1 行的**"下载日期："**改成当天——后面 §6 的对撞公式要用它做检查点。

## 4. 销量是怎么算出来的（核心口径）

### 4.1 原始数据长什么样

All Orders 报告**一行 = 一个订单项（item）**，不是一单。关键字段：
`amazon-order-id / purchase-date / order-status / fulfillment-channel / sales-channel / sku / asin / quantity / item-price`。

### 4.2 辅助列：日销表的"口径引擎"

原始列右边手工加了几列公式（各文件的列位不同，公式一致）：

| 辅助列 | 公式（原样摘录） | 作用 |
|---|---|---|
| `purchase date` | `=LEFT(C3,10)` | 从 ISO 时间戳截出**下单日期**（C 列=purchase-date） |
| `有效性` | `=IF(AND(E3<>"Cancelled", MID(G3,1,7)="Amazon."),1,0)` | 有效订单打 1（E=order-status，G=sales-channel） |
| `地区`（北美） | `=IF(G3="Amazon.ca","加拿大",IF(G3="Amazon.com.mx","墨西哥","美国"))` | 按站点映射国家 |
| `地区`（欧盟） | `=IF(G3="Amazon.co.uk","英国","欧洲")` | 英国与欧盟分开 |
| `型号` | （查商品资料） | 报表可读性 |
| 键列（北美） | `AM2 =G2&L2`（渠道&SKU）、`AQ2 =L2&AP2`（SKU&地区） | 透视/对撞用联合键 |

### 4.3 "有效性"的三条规则（逐条拆）

1. **`E3<>"Cancelled"`** —— 剔除取消单。注意：**Pending（待确认付款/未发货）不算取消，算销量**（印度站样例：order-status=Pending、item-status=Unshipped 照样计）。
2. **`MID(G3,1,7)="Amazon."`** —— sales-channel 必须以 `Amazon.` 开头。排除 Non-Amazon（站外渠道单）。
3. **北美特例**：`=IF(AND(E3<>"Cancelled", OR(ISNUMBER(FIND("TEMU",B3)), MID(G3,1,7)="Amazon.")),1,0)` —— merchant-order-id（B 列）里带 **TEMU** 字样的也算有效，因为 **Temu 半托管发 FBA 的单**走主账号履约，要计入销量。

### 4.4 透视：从明细到"各国销量"

`数据透视表`/`数据透视图` 的固定姿势：

- **筛选器**：`有效性 = 1` + `purchase date`（手动勾选归属月的日期范围，所以表里显示"(多项)"）
- **行标签**：`sales-channel`（北美版用 `地区` 列，按国家聚）
- **值**：`求和项:quantity`（**件数**，不是订单数）

例（北美 202609 透视输出）：`Amazon.ca 876 / Amazon.com 2656 / Amazon.com.mx 916`。

### 4.5 口径要点（和月度管线对齐的部分）

- **按下单时间（purchase date）归属**，不按发货/结算时间——所以月初做上月报表时，要重导一次报告把"迟到"的订单收进来。
- **时区**：时间戳是站点本地时区（欧/美 `+00:00`，日本 `+09:00`），`LEFT(…,10)` 截的就是报告里写的那个日期，不做二次时区换算。
- 上级 trunk 管线的销量口径同样是"下单日 + 剔取消 + quantity 求和"，但它是**直接重读原始报告**算的，多语言取消词映射在那边维护（`status_map`、雷区 11/17）。日销表的透视数字可与月销总表对撞，**两边对不上先查：报告重导了没有、透视图筛选还挂在归属月上没有**。

## 5. 库存是怎么算出来的

### 5.1 两份库存报告的分工

| 报告 | 长相 | 进哪个 sheet | 回答的问题 |
|---|---|---|---|
| FBA **结余**（Ledger 结余） | FNSKU/ASIN/MSKU/**Disposition**/**Ending Warehouse Balance** 五列 | `可售库存`（单站点版）、`美国`/`加拿大`/`墨西哥`（北美版） | 某天账面结存多少（Disposition=SELLABLE 即可售结存） |
| FBA **清单**（Inventory，afn-*） | 20+ 列全字段快照（含在途三态） | `在途库存`（单站点版）、`{国家}可售+在途库存`（多站点版） | 库存此刻的**状态构成**（可售/预留/不可售/在途三态），字段详解见配套库存文档 |

### 5.2 清单表上的加工列（每个可售+在途 sheet 都有）

以北美 `美国可售+在途库存` 为例（列位）：

```
J=afn-warehouse  K=afn-fulfillable  L=afn-unsellable  M=afn-reserved  N=afn-total
P=afn-inbound-working  Q=afn-inbound-shipped  R=afn-inbound-receiving  W=afn-onhand-buyable
```

第 1 行的人工标签就是加工列的名字：`不可售数量(L) / 预留(M) / 在库在途(N) / 刚发的货(P) / 在运输中的货(Q) / 亚马逊准备接收的货(R) / 现货(W)`。

```excel
Y3 =P3+Q3+R3                          ← "在途库存" = working+shipped+receiving 三态加总
Z3 =COUNTIF('美国-每日库存分析表'!A:A,A3)   ← 该 SKU 名下有几票在途货件
X1 =SUMIF(美国!C:C,A3,美国!E:E)         ← 从结余表把该 SKU 的结存拉过来（北美版）
```

> **P/Q/R 三列就是亚马逊库存状态里的 working / shipped / receiving**（详见配套文档《各国库存状态与转换原理》）。

### 5.3 库存记录：每日快照矩阵（`{国家}库存记录`）

结构（以 `美国库存记录` 为例）：

- **B 列** = SKU 清单；**C 列起** = 一天一列，列头两行：`星期几（带"单周六/双周六"大小周标记）` + `日期`。
- **每天下载清单报告后，把当日 K 列（可售）按 SKU 粘贴成新的一列**——这就是"日销表"里"日"字的由来：手工累积的每日库存时间序列。
- **第 1 行** `=SUM(C$5:C$19957)` = 当日全站可售合计（第 2 行标签"在售库存"）。
- **A 列** `=VLOOKUP(B:B,'美国-每日库存分析表'!A:D,4,0)` —— 从分析表把该 SKU 的状态拉过来展示。
- 日期列不是天天都填——**下载了才填**（观察到的列：9/1、9/7 有值），所以中间空列是正常的。

### 5.4 每日库存分析表：在途货件矩阵（核心工具）

结构（以 `英国-每日库存分析表` 为例）：

```
第 1~4 行：每列一票货件 —— 货件号(FBA15M2DGRR3)、发货日期(7/22)、预计时效(35天)、预计到货(=发货+时效)
第 5 行起：SKU 明细 —— A:SKU  B:型号  C:国家/分类  D:渠道状态(在售)
           E:预留库存  F:可售库存  G:在途  H:调拨在途合计  I,J,K,L...: 各票货件的数量
```

关键公式：

```excel
F7 =SUMIF('英国可售+在途库存'!A:A,A:A,'英国可售+在途库存'!Y:Y)      ← 可售库存 = 清单表 Y 列(现货)按 SKU 求和
G7 =VLOOKUP(A:A,'英国可售+在途库存'!A:AA, COLUMN(...!$AA$2),0)      ← 在途 = 清单表在途合计
H7 =IF(ISNUMBER(FIND("到货",$I$5)),0,IF(I7="",0,I7))
   +IF(ISNUMBER(FIND("到货",$J$5)),0,IF(J7="",0,J7))+…             ← ★"到货自动剔除"
```

**H 列"调拨在途合计"的妙处**：每票货件列的表头（第 5 行）一旦手工写上"X月X日到货"字样，`FIND("到货",…)` 命中，这一列就自动从"在途"里剔除——**到货动作 = 在表头补写'到货'两个字**，不用动公式。

**条件格式预警**（第 1 行图例，原样摘录）：

| 颜色 | 触发条件 |
|---|---|
| 粉红 | 缺货 |
| 橙色 | 新品未上架 |
| 红色 | 销量高于上月日均销量的 2.5 倍，且上月日均销量高于 1.5（爆卖预警，防止断货） |
| 蓝色 | 销量低于上月日均销量的 3 倍（即不足上月日均 1/3，滞销预警） |

> 欧盟版还有一张变体：`意大利`/`法国`/…/`爱尔兰` 十个国家 sheet（每个欧盟国家一张），
> 结构是 `SKU | 品名 | {国家} | Amazon.{it} | 库存 | 实时速度 | 上月日均 | 上月总销量 | 近期每日销量列...`，
> 图例同上——这是**按国家的销量速度+库存监控表**，与英国/欧洲两张分析表并行。

## 6. 对撞校验：表自己会报警

`数据透视图`（北美版）里埋着三组自检公式，**每次下载数据后都要瞄一眼**：

```excel
H1 =TODAY()   G1 =H1-1   H5=下载日期     ← ① 下载日期是否昨天的（没更新数据会在这里现形）
I2 =VLOOKUP(H2,J:K,2,0)+…='美国-每日库存分析表'!AH6
                               ← ② 透视表的该国销量合计 == 分析表上的合计（口径对撞）
B3 =IF(VLOOKUP(分析表!A6, 分析表!A:CJ, …+DAY(数据透视图!$H$5-1),0)=0,"无数","TRUE")
                               ← ③ 分析表当天那一列到底有没有数（"无数"= 库存快照没粘贴）
```

加上 §5.4 的颜色预警，这套表有四层"数字对不上就亮灯"的机制。

## 7. 作业流：这套表是怎么"做"出来的

### 7.1 每个下载日（约每周 + 大促前后）的动作清单

1. 后台下载 **All Orders 订单报告** → 粘贴到 `每日销售数据`（表头对齐第 2 行，新行自动带辅助列公式）。
2. 后台下载 **FBA 结余 + FBA 清单** → 结余贴 `可售库存`/`美国…`；清单贴 `在途库存`/`可售+在途库存`。
3. **改所有 sheet 第 1 行"下载日期"为当天**（透视图 TODAY()-1 对撞会检查）。
4. 当日**可售数（K 列）按 SKU 粘贴**进 `库存记录` 的新日期列（列头写星期+日期）。
5. 有新货件 → 在 `每日库存分析表` 加一列（货件号/发货日期/预计时效）；**已到货的货件把表头写上"X日到货"**。
6. 刷新透视，**检查筛选器**：有效性=1、purchase date 框在归属月。
7. 瞄一眼 §6 的三组对撞公式 + 分析表颜色预警。

### 7.2 月底动作

- 透视筛选切到完整归属月，把各国销量抄给需要的人（或与月销总表对撞）。
- 整本另存 `{年月}-{文件名}.xlsx` → `2026年每日数据\2026年9月\` 归档。
- 根目录的工作副本继续当**下月**的表用（注意 §2.3 说的"10月销量"静态表头要更新）。

## 8. 已知的坑（从表里实际看到的）

| # | 坑 | 现场 | 处置 |
|---|---|---|---|
| 1 | **日本清单表表头乱码** | `可售+在途库存` A2:N2 是 `?壠 G / 攝憲悚? G / 彜昳柤徧…`（日文报告被错误解码） | 别按表头找列，**按列位**（J/K/L/M/N 与其他站一致）；根目录 `file_chardetect.py` 就是上级为这类事准备的 |
| 2 | **北美结余表 #VALUE!** | `美国`/`加拿大`/`墨西哥` sheet 出现 `#VALUE!` | 旧公式引用断链，结余数据以 `可售+在途库存` 的 X 列 SUMIF 为准即可 |
| 3 | **E 列预留库存断链** | 分析表 `E7 =IFERROR(VLOOKUP(A:A,#REF!,7,0),0)` 返回 0 | 该列已废，预留看清单表 M 列 |
| 4 | **库存记录有空列** | 9/2~9/6 等列没值 | 正常——没下载就没粘；别把空列当"卖光了" |
| 5 | **"10月销量"陈旧表头** | 美客多/罗马尼亚 `产品类型` B 列 | 换月时改表头+重填值，IFS 分类依赖它 |
| 6 | **报告语言漂移** | 美客多 202608 中文版 → 202609 西语版；eMAG 英/中文切换（上级管线雷区 11/17） | 粘贴前核对列名语言，对不上号先确认导出版本 |
| 7 | **表名带空格** | `英国库存记录 `、`墨西哥-每日库存分析表 ` 尾随空格 | 脚本读表用 `strip()` 匹配，别手打 sheet 名 |

## 9. 术语速查

| 术语 | 含义 |
|---|---|
| 日销表 | 本文这套"库存销售表"工作簿的统称 |
| 归属月 / 归属周期 | 一笔订单算哪个月的销量——按 purchase date 所在月份 |
| 快照 | 下载库存报告那一刻的全量库存状态 |
| 在途 | 已创建货件但还没接收完的货（working+shipped+receiving，见库存文档） |
| 在售库存 | 清单表 K 列（afn-fulfillable），库存记录矩阵里粘的就是它 |
| 货件（shipment） | 一次发货计划，FBA 开头货件号，分析表里一列一票 |
| 卡航 | 卡车航空联运的陆运渠道（分析表列头"7/22卡航8/23到货"） |
| 大小周 | 列头"单周六/双周六"标记的是隔周休息的日历 |
| Pan-EU / 本地履约 | 欧盟泛欧计划：库存放一国、卖全欧；`quantity-for-local-fulfillment` 是各国本地可履约量 |
| MFN / AFN | 卖家自配送 / 亚马逊履约（FBA），mfn-* / afn-* 字段前缀 |
