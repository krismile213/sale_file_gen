# 统计：手工版时期，新的 SKU 是怎么进来的（2026-10-23）

> 动机：本次把「新品补行」自动化之后，想复盘手工版时一个新 SKU 靠什么途径进日销表，
> 验证自动化的三条判据（货件 / 库存 / 销量）是否覆盖了真实路径，以及有没有漏掉的入口。

## 一、数据源与口径

| 源 | 用途 |
|---|---|
| `断货分析/型号首库存登记.xlsx`（468 SKU + 5368 站点明细） | 每个 SKU 的首次出现日 / 首可售日 / 首在途日 |
| `trunk/data/数据归属周期/202610/货件/**/*.tsv`（81 个） | 货件报告里出现过的 SKU 集合 |
| `1.每日销售数据表/` 16 张分析表 | 货件列（行 1 货件号）是否有该 SKU 的记录 |

**四条路径定义**（按证据强度排序，一个 SKU 只归一类）：

- **A 货件驱动** —— 出现在货件报告里（发货单来了，运营加行）
- **B 库存驱动** —— 货件报告里没有，但库存报告直接出现可售（直接入仓 / 调拨）
- **C 在途驱动** —— 只有库存报告的在途痕，从无可售
- **D listing 驱动（幽灵）** —— 库存报告里 listing 出现过，但可售/在途都是 0

## 二、总体结果（468 个 SKU）

| 路径 | 9 月首现（445 个） | 10 月首现（23 个） |
|---|---:|---:|
| A 货件驱动 | **399（90%）** | **13（57%）** |
| B 库存驱动 | 37（8%） | 4（17%） |
| C 在途驱动 | 0 | 0 |
| D listing 驱动（幽灵） | 9（2%） | 6（26%） |

**手工版时新 SKU 九成靠货件报告进来**：发货单一到（TSV），运营就按货件号在分析表
加一行、把数量填到对应货件列。这是唯一成规模的入口。

## 三、货件报告的细节

- 81 个货件 TSV → **422 个去重 SKU / 86,555 件**。
- 货件 SKU 的首现月份：**95% 是 9 月首现**（老 SKU 补货），10 月首现的只有 13 个
  （3,739 件，全是 FBA19PX7QT4G 那批加拿大/印度/墨西哥的新品）。
  ⇒ 货件不是「每月一批全新 SKU」，而是**滚动的新品流 + 大量补货**。
- 「状况」列全部 422 个都写着「新品」——这是备货类型字段，**没有区分度**，
  不能拿它判断 SKU 新旧（判断新旧只能靠首现日期）。

|---|---|---|---|---|---|

两个值得注意的点：

1. **G598 的货件痕比同批晚 8 天**（首在途 10/14 vs 同批 10/06）——同一货件号，
   发货有先后，货件列的「到货日」不能一刀切。
2. **G599~G601 不在任何已下载货件里**，但 listing 已经在 4 个站点出现。它们和
   G592~G598 是同一批新品（Redmi Note 17 系列），货件报告**还没下载**。
   手工版流程下这三个 SKU 现在**任何表里都看不到**——没有库存、没有销量、
   没有货件单，运营无从发现。这正是「哪怕没有销量也登记」要解决的盲区。

## 五、对自动化的验证结论

runner 的三条补行判据覆盖情况：

| 手工版路径 | 自动化对应 | 覆盖 |
|---|---|---|
| A 货件驱动（90%） | `apply_shipments` 按货件报告补行 | ✅ |
| B 库存驱动（8%） | 库存源 SKU + listing 活着 → 补行 | ✅ |
| C 在途驱动（0%） | 同上 | ✅ |
| **D listing 驱动（幽灵）** | **同一条判据（库存源出现即补）** | ✅ 且是**手工版做不到的** |
| 销量驱动 | `_SITE_CHANNEL` 按渠道补行 | ✅ 补充（实际只捞到 2 个缺口） |

**结论：手工版的入口自动化全覆盖，且多抓了手工版看不见的 26%（10 月口径）。**
手工版时零库存 listing 永远不会进表，等运营发现时往往已经断货；

## 六、方法学坑（复用时注意）

1. **货件列会滚动复用**：分析表全体 4,442 行里只有 47% 在货件列留有记录，
   但这是老 SKU 的货件被后发货件挤掉导致的，**不能用来统计历史进入路径**。
   统计「新 SKU 怎么进来」必须用登记表的日期字段 + 货件 TSV 全集交叉。
2. **「多国库存」报告是噪音源**：站点明细里 10 月首现的 1,278 行中 44% 是幽灵，
   其中「多国库存」占 446 行——Pan-EU 报告会把所有 listing 都列出来，
   不管有没有库存。按站点统计时要把它单独看。
3. **货件 TSV 是纵表**：前 6 行元数据 + `卖家 SKU` 表头行 + 明细，
   字段可能带引号（`"--"`），用 `csv.reader(delimiter='\t', quotechar='"')`。
