## 一、一句话结论

**两个清单不是同一批 SKU，差在「在途算不算」和「没销量算不算」这两个口径上，不是数据错。**

- 我们的旧版（V3）报印尼 **13 个**，里面 **8 个其实有货在路上**（计划到货 11-04 / 11-18），只有 **5 个是真断货**。
- 霞姐口径若按「在售 + 无现货 + 无在途」，印尼是 **34 个**，多出的是 **29 个「从未备货」**（今年一件没进、也没卖过），它们不是断货事件。
- 两边的交集正好是那 **5 个真断货**。

## 二、口径差异的两个技术根因

### 根因 1：库存「在途」的含不含计划到货

| 数据源 | 字段 | 含义 |
|---|---|---|
| 商品资料 stock 页 | `In transit` | **含已排产/已下单、尚未发运的计划到货**（对应 0923 / 1009 / 1021 / 1104 / 1118 / 1202 到货周列） |
| 日销表主表 | `剩余库存+在途库存` | 只含**已发运的实际在途** |

V3 用的是后者，所以把「已排产但还没发」的 SKU 判成了零在途。

**实证**：V3 判为断货、实际有在途的 8 个印尼 SKU，其「在途」全部能对上未来到货周：

| SKU | In stock | In transit | 0923 | 1009 | 1021 | 1104 | 1118 |
|---|---:|---:|---:|---:|---:|---:|---:|
| G552 | 0 | 8 | 0 | 0 | 0 | **8** | 0 |
| G567 | 0 | 6 | 0 | 0 | 0 | 0 | **6** |
| G569 | 0 | 6 | 0 | 0 | 0 | 0 | **6** |
| G572 | 0 | 55 | 0 | 0 | 0 | **55** | 0 |
| G577 | 0 | 132 | 0 | 0 | 0 | 0 | **132** |
| G578 | 0 | 132 | 0 | 0 | 0 | 0 | **132** |
| G579 | 0 | 132 | 0 | 0 | 0 | 0 | **132** |
| G580 | 0 | 132 | 0 | 0 | 0 | 0 | **132** |

合计 503 件，全部落在 11-04 / 11-18 两个到货周，没有一件是"失踪库存"。

### 根因 2：在售判据的源头不同

| 判据来源 | 印尼分布 | 问题 |
|---|---|---|
| 日销表 J 列「印尼状态」 | 在售 239 / 机会 68 / 需求 46 / 售完截止 36 | 「机会」「需求」语义模糊，且与商品资料打架 |
| 商品资料 `Indonesia stock` C 列「状态」 | 在售 342 / 售完即止 10 / 停售 1 | 霞姐唯一权威口径 |

**两边直接冲突的有 110 个 SKU**：

| 日销表 J 列 | 商品资料状态 | 数量 |
|---|---|---:|
| 机会 | 在售 | 67 |
| 需求 | 在售 | 39 |
| 在售 | 售完即止 | 2 |
| 在售 | 停售 | 1 |
| 机会 | 售完即止 | 1 |
| 售完截止 / 需求 | 商品资料未收录 | 36 |

这就是你说的「被印尼的在售列干扰」——**日销表 J 列不能作为在售判据**，应该以商品资料状态列为准。

## 三、印尼：34 与 13 的完整拆解

同一批「在售 + 无现货」的印尼 SKU，按是否补货、是否卖过分四档：

| 档 | 定义 | 数量 | 是否断货事件 |
|---|---|---:|---|
| **A 真断货** | 无现货 + 无在途 + 今年有销量 | **5** | ✅ 是，需决策补货 |
| B 缺货在补 | 无现货 + 有在途 + 今年有销量 | 35 | ❌ 否，货在路上 |
| C 从未备货 | 无现货 + 无在途 + 今年零销量 | 29 | ❌ 否，选品/上架问题 |
| D 新备货未开卖 | 无现货 + 有在途 + 零销量 | 20 | ❌ 否，观察 |

- 霞姐口径「在售 + 无现货 + 无在途」= **A + C = 34 个**
- 我们 V3 报的 13 个 = **A 的 5 个 + B 里的 8 个**（那 8 个就是根因 1 那批）
- 交集 = A 档 5 个：**G178、G257、G402、G422、G576**

**所以「有出入」的实质**：
- 我们多了 8 个（有在途被当无在途）
- 霞姐多了 29 个（从未备货被我们单列、没进断货清单）
- 真正两边都认的只有 5 个

## 五、泰国为什么是 0

不是漏算，是泰国补得最干净：

- 泰国 333 个 SKU，在售 324
- 零现货的 26 个，**26 个全部已有在途**（26/26）
- 所以「在售 + 无现货 + 无在途」= **0**

V3 报的泰国 G564，在途 9 件，属于「缺货在补」，不是断货。

## 七、建议的动作

1. **断货口径统一写死**：`在售（商品资料状态列）+ In stock ≤ 0 + In transit ≤ 0 + 今年有销量`。
   在途一律以商品资料的 `In transit` 为准（含计划到货），因为那是备货决策的依据。
2. **「从未备货」单独一页**，不混进断货清单。印尼 29 个是选品问题（其中一部分还是 C 级长尾），需要业务判断要不要上架，不是补货问题。
3. **日销表 J 列「印尼状态」不再作为判据**，只做参考展示。两边 110 个 SKU 打架，靠人脑记不住。
4. **商品资料的状态列要加站点维度**（已在上封邮件问过）：同一个 SKU 在不同国家状态可能不同，现在三个国家各一张表，是天然分站的，这一点已经没问题；但如果未来合并成一张总表，必须保留站点列。
