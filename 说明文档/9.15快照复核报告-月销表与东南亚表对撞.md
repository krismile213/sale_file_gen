## 九、🇵🇭🇹🇭 菲/泰「月销表 vs 工作簿数据」差额之谜 —— **已完全解开（非 bug）**

> 用户 9.16 报障：「月销表计算出来的菲律宾，泰国，印尼销量，**只有印尼是一致的**
> 只算平台的按理来说是对的，但是最终的有差别，我还在排查。
> 菲律宾 **5972 VS 5874**(数据)；泰国 **3342 VS 3274**（数据）」

### 9.1 结论一句话

**月销表的「菲律宾」/「泰国」列 = 本土 + 跨境，不是"只算平台"。**
差额就是那笔**跨境 Lazada**：

```text
菲律宾 5972 = 虾皮2015 + Lazada755 + 抖音945 + 线下KSON2132 + 跨境Lazada 125
泰国   3342 = 虾皮2895 + Lazada379                        + 跨境Lazada  68
印尼   3868 = 虾皮 997 + 抖音309 + 线下上马2562            （印尼无跨境站 → 恒为 0）
```

### 9.2 为什么

代码 `sum_se_local_site()`（`month_sale_file.py` 第 **882** 行）：

```python
# 三个本土销售市场，都要统计跨境数量          ← 注释原文就写着「都要统计跨境」
cur_group_month_sale_df = total_sku_sale_df2[total_sku_sale_df2["站点"] == group].copy()
```

**只按 `站点` 过滤，不限 `实体`**。而跨境订单在 `get_belonging_lazada_order_df()`（第 **443** 行）里：

```python
order_df["站点"] = sale_group      # 跨境 Lazada 泰国 → 站点 = "泰国"
order_df["实体"] = "跨境"           # 只有实体标了跨境
order_df["仓库"] = "旭艺仓"
```

→ 跨境订单的 `站点` 与本土**同名**，自然被并进同一列。
