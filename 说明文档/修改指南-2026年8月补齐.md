## 任务⑨ 东南亚汇总销量列名依赖 pandas 版本 → 新版下**整块清零**  ✅ **9.14 已修复**

### 症状

实施任务⑧ 后重跑，【2026年】**东南亚相关分组（菲律宾/泰国/印尼/新加坡/马来/越南/虾皮境内/东南亚）全部变成 0**，总计从 73214 掉到 58092；而欧洲/亚马逊等其他分组**完全正常**。

### 根因（逐层定位）

1. `se_a_sku_sale_df` 的销量列**名**不对：实跑为 **`数量`**，而代码 `rename(columns={"数量dropna": …})` 去重命名一个**不存在的列名**——`rename` 对不存在的键**静默跳过**，于是列名保持 `数量`。
2. `pd.concat([amazon_sale_df, se_a_sku_sale_df, other_sku_sale_df])` 后，亚洲际行的 `202608销量` 列全为 `NaN`。
3. 下游 `sum_se_single_site()` 按 `f"{YYYYMM}销量"` 取数 → 全 0。

**为什么列名会不一致**：`groupby(...)["数量"].sum()` 的聚合列名随 pandas 版本而异 —— 旧版 pandas 中 `dropna` **不是** groupby 的合法参数，会被当作 `sum()` 的 kwargs，结果列名变成 **`数量dropna`**；pandas ≥2.1 起 `dropna` 是合法参数，列名就是 **`数量`**。本机为 pandas **3.0.5**，故为 `数量`。

**佐证**：同文件 `other_sku_sale_df`（1095-1096 行）是**完全相同的 groupby 写法但 rename 写的是 `{"数量": …}`** → 一直正常；只有 `se_a_sku_sale_df` 写成 `{"数量dropna": …}`。

### 修复

```python
    # groupby聚合后的销量列名随pandas版本而异（旧版为"数量dropna"，新版为"数量"），两种都兼容
    se_a_sku_sale_df = se_a_sku_sale_df.rename(columns={"数量":f"{cur_acct_cycle_date.strftime('%Y%m')}销量","数量dropna":f"{cur_acct_cycle_date.strftime('%Y%m')}销量"})
    assert f"{cur_acct_cycle_date.strftime('%Y%m')}销量" in se_a_sku_sale_df.columns, "东南亚销量表列名重命名失败（groupby聚合列名与预期不符）"
```

### 教训

- **不要把 `rename` 当断言用**——列名不匹配时它静默通过，错误会一路漂到成品里，且只影响局部（其它分组正常，极难发现）。
- **依赖 pandas 自动生成的列名很危险**，尤其是 `groupby(...)[col].sum()` 这种简写。要稳就显式指定，或加断言兜底。
- 每月跑完**抽查东南亚块非 0**（`HR` 列），这是最快的体检点。

```python
def recalc_excel(path, timeout=60):
    """用 Excel/WPS 的 COM 接口"打开→全量重算→保存→关闭"，让公式格带上缓存值。
    本机已注册 Excel.Application / KET.Application，无需安装 pywin32；
    失败只提示、不中断（成品仍可用，Excel 打开时会按 fullCalcOnLoad 自动重算）。"""
    ps = ("$ErrorActionPreference='Stop';"
          "$xl=New-Object -ComObject Excel.Application;$xl.Visible=$false;$xl.DisplayAlerts=$false;"
          f"$wb=$xl.Workbooks.Open('{path}');$xl.CalculateFullRebuild();"
          "$wb.Save();$wb.Close($false);$xl.Quit()")
    try:
        subprocess.run(["powershell", "-NoProfile", "-NonInteractive", "-Command", ps],
                       timeout=timeout, check=True, capture_output=True)
        print("🔁 已重算并回写公式缓存值（WPS/预览器/程序读取也能拿到数）")
    except Exception as e:
        print(f"【提示】重算回写失败（不影响结果，Excel 打开时会自动重算）：{e}")
```

设计：**字典（精确串）+ 5 条正则 + 「必须中文结尾」约束**。

```python
_MONTH_EN   = {...}   # 1月→Jan … 12月→Dec，以及 累计/Cumulative 等
_SITE_EN    = {...}   # 站点/主体 → 英文；⚠️ 台湾 → "Taiwan, China"
```

- 所有正则**都要求原文以中文结尾**（如 `总销量$` / `销量$`）。翻完之后该格尾部已是英文，**再跑不再匹配** →

```python
for sn in list(wb.sheetnames):
```

**成因链**（模板 Singapore 表）：

1. 模板里有一条 **hidden、零宽** 的形状：`<xdr:cxnSp>`（Excel 里叫"直接连接符 1"）；

**修法**：新增 `_prune_dangling_rels(part, data, present, blobs)`，并在 `restore_wps_parts` 的两个写回分支各接一次。

⚠️ **判据必须两个条件同时满足**：`Target` 不在输出包内 **且** 已无任何引用它的 owner XML ——
只看"Target 在不在包里"会**误删**（有的部件只是稍后才写）。若某 `.rels` 里的关系全被删空，则**整份 `.rels` 不写**。

### 任务⑯-e：两个模式的判据不同（`inherit` 开关，刻意设计）

| 模式 | `inherit` | 判据 | 用途 |
|---|---|---|---|
| `--apply` | **True** | **继承上期分类**：上期是 X 且当月仍无起量 → 保持 X（尊重历史判定，不凭空毕业） | 真正生成要用的列 |
