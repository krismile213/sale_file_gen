## 2. 目录约定（脚本靠这些相对路径找数据）

```
<仓库根>/
├─ requirements.txt
├─ trunk/                     ← 所有脚本都在这里，也是"运行基准目录"
│  ├─ month_sale_file.py      主脚本（生成月销售总表）
│  ├─ southeast_asia_sale_file.py / europe_sale_file.py / north_america_sale_file.py
│  ├─ age_report.py           库龄总表（主脚本任务⑰会调用，也可单独跑）
│  ├─ 商品资料.xlsx           ★ 主数据，必需；四个脚本都读它
│  ├─ data/数据归属周期/<YYYYMM>/快照日期/<YYYYMMDD>/   原始报表 + 当月模板
│  ├─ data/数据归属周期/<YYYYMM>/库龄/                  库龄原始报表
│  ├─ data/库龄报表/亚马逊EMAG库龄情况总表.xlsx          库龄总表（逐期累积）
│  ├─ sale_file_tmp/          中间件 csv（主脚本产出，下游三个脚本消费）
│  └─ result/                 成品（月销售总表 / 东南亚 / 欧洲 / 北美）
├─ Daily_Sales_Report/        ← 日销表（独立管线，详见该目录下 README-入库范围与依赖.md）
```

**★ 换机最容易漏的：`trunk/商品资料.xlsx`**。它不在代码里生成，缺了主脚本第一行就报错。
仓库里已纳入版本控制；如果你本地删了它，`svn revert` 或用上一版覆盖回来。

## 3. 运行顺序（顺序不能反）

```bash
cd trunk
python month_sale_file.py              # ① 主脚本：产出 月销售总表 + sale_file_tmp/*.csv
python southeast_asia_sale_file.py     # ② 东南亚（10 个 sheet）
python europe_sale_file.py             # ③ 欧洲
python north_america_sale_file.py      # ④ 北美
```

- ②③④ **必须**在①之后：它们读的是①写出的 `sale_file_tmp/total_sku_sale_df.csv` 等中间件，
  不能并行、不能拿上期的中间件顶替。
- 每轮 ≈60 秒。重跑前关掉正在预览的成品 Excel，否则会退化为原地覆写并可能残留 `~$` 锁文件。
- 月份 / 快照日 / 得分列名在主脚本 `if __name__ == "__main__":` 头部改，一共 3 行（各下游脚本同样 3 行）。

## 4. 工作目录：已做自愈，不再要求手工 cd

主脚本内部路径是相对写法（`data/数据归属周期/...`、`sale_file_tmp`），历史上必须以 `trunk/` 为 CWD。
2026-11-02 起在 `if __name__ == "__main__":` 里加了守卫：**入口不是 trunk/ 时会自动切过去并打印一行提示**，
CWD 正确时是完全空操作。所以下面几种写法现在都等价：

```bash
cd trunk && python month_sale_file.py          # 传统写法，不变
python trunk/month_sale_file.py                # 仓库根目录直接跑，OK
```

三个下游脚本本来就用 `__file__` 拼绝对路径，与 CWD 无关。

## 5. 跑挂了先查这三件事

1. `商品资料.xlsx` 在不在 `trunk/` 下、得分列（`N月销量得分`）有没有当月那一列；
2. `data/数据归属周期/<期>/快照日期/<日>/` 里当月模板在不在（模板一律**复制当月成品**，别用上上期）；
3. 报表文件名是否按约定（亚马逊「欧洲」站现在实际按**欧盟**导出，脚本有别名兜底；
   菲律宾新报告 `ESTP易速菲-...` 会按通配兜底）。先用 `python 工具-换月资料体检.py <归属月> <快照日>` 体检一遍。

## 6. 日销表（`Daily_Sales_Report/`）：另一套管线，独立跑

日销表不生成 `月销售总表`，它维护 `1.每日销售数据表/` 下的 **12 份工作簿**。

```bash
cd Daily_Sales_Report
python pipeline/run.py                 # 日常只记这一条（自带前体检，缺报告会中止，退出码 2）
python pipeline/run.py --dry-run       # 只打印计划，不写任何文件 ← 换机后先用这个试
```

**与月销表的关系：共用输入、不共用输出。** `pipeline/core/` 只读 `trunk/data/数据归属周期/`
的平台原始报告，**不读** `trunk/result/` 的成品，所以两条管线顺序无关、可以各自单独跑。

**放哪里是硬要求**：`Daily_Sales_Report/` 必须与 `trunk/` 平级，都在仓库根下。因为

```python
DSR       = 上溯找「含 1.每日销售数据表 的目录」   # → <仓库根>/Daily_Sales_Report
PROJECT   = dirname(DSR)                          # → <仓库根>
SNAP_BASE = PROJECT/trunk/data/数据归属周期        # 靠上面两步才对得上
```

挪进 `trunk/` 里就会变成 `trunk/trunk/data` —— 必崩。

**检出后必做一件事**：把 12 份工作簿拷回 `1.每日销售数据表/`（清单见该目录 README）。
⚠️ 缺工作簿时体检**不会**提醒你：`precheck.py` 那句 `✅ 13 本均可写（无占用）` 只统计
`config.WORKBOOKS` 的条数，不检查文件是否存在（2026-11-02 实测，工作簿全缺仍打绿勾）。
唯一可靠判据：`ls 1.每日销售数据表/*.xlsx | wc -l` 必须等于 **12**。
