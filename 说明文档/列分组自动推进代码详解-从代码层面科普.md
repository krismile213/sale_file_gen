**这段代码的做法是：把 ZIP 拆开 → 用正则表达式改其中一个 XML 文件里的几行字 → 重新打包成 ZIP。**
全程没碰 Excel 软件本身，就是纯文本处理。所以**不需要装 Excel、不需要开宏、也不会有"启用宏"的安全提示**。

> 💡 **一句话**：VBA 是"遥控器，指挥 Excel 去干活"；这段代码是"绕过 Excel，直接改文件"。

### 顺带说：这段代码里确实用到了 openpyxl，但仍不是宏

`fill_excel_from_df()`（104 行）用了 `load_workbook()` / `wb.save()`，这是 **openpyxl** 库——
它也是个"直接读写 xlsx" 的纯 Python 库，同样走 ZIP+XML 路线，跟 VBA 毫无关系。

**为什么 `arrange_month_outline` 不直接用 openpyxl，而要手动拆 ZIP？**
因为 **openpyxl 没有提供设置"列分组"（分级显示）的 API**。这个功能在 Excel 界面里叫
「数据 → 分级显示 → 组合/取消组合」，openpyxl 只能读写单元格，管不到这个。
所以只能退到更底层，自己改 XML。

## 二、这段代码在解决什么业务问题

### 2.1 什么是"列分组"

【2026年】这张表有 **297+ 列**，因为每个销售分组都有 **12 个月列**：

```
欧洲 | 1月 2月 ... 12月 | 英国 | 1月 2月 ... 12月 | 美国 | ... 总计 | 1月 ... 12月 | 属性列
     └── 12 列 ──┘          └── 12 列 ──┘
```

Excel 的「分组（分级显示）」功能能让这些月份列**折叠**起来，只留一个小 `+` 号。
这样平时看表不会横向拖到晕，需要时点开。

**折叠起来的列在文件里长这样**（`<cols>` 是 xlsx 里管列属性的标签）：

```xml
<col min="13" max="24" outlineLevel="1" hidden="1"/>   <!-- 这一块 12 列折起来了 -->
<col min="25" max="25" collapsed="1"/>                  <!-- 这一列旁边有个 + 按钮 -->
```

- `outlineLevel="1"` = 属于第 1 级的组
- `hidden="1"` = 隐藏
- `collapsed="1"` = 在**这一列之后**显示一个折叠按钮
- `outlineWidth` / 无 `outlineLevel` = 不分组

### 2.2 为什么需要"自动推进"

模板里录的是**上个月**的状态。比如模板做好时是 7 月，那：

| | 模板（7 月态） | 8 月跑出来应该变成 |
|---|---|---|
| 【2026年】 | 1~7 月平铺，8~12 月折叠 | **1~8 月平铺，9~12 月折叠** |
| 欧洲表 | 1~6 月只留合计列，7 月展开，8~12 隐藏 | **1~7 月只留合计列，8 月展开，9~12 隐藏** |

**以前这一步是人工做的**：打开成品 → 拖到 8 月 → 选中 9~12 月那堆列 → 取消组合 → 再选中 8 月列 → 组合 → 保存。
**每个月都要手工来一遍，容易漏、容易点错。** 任务⑩ 就是把这个动作写成代码，跑完脚本自动完成。

> 这就是你说的"自动组合解除组合"——**组合 = 把当月的列展开、把未来的列折起来；解除组合 = 把上个月的折叠打开**。
> 加上"格式"部分，就是同时设置好打开时的横滚位置。

## 四、逐函数详解

### 4.1 `_sheet_xml_map()`：sheet 名 → XML 文件名

**问题**：XML 文件叫 `sheet1.xml`、`sheet2.xml`，但我们要找的是【2026年】和【2026年-欧洲各国每月销售情况】。
中间隔着两张对照表：`workbook.xml`（sheet 名 → rId）和 `workbook.xml.rels`（rId → 文件路径）。

```
"2026年"  ──workbook.xml──▶  rId="rId3"  ──workbook.xml.rels──▶  "worksheets/sheet1.xml"
```

代码就是走这条链（1093-1106 行）：

```python
relmap = {}                                    # rId → Target
for tag in re.findall(r"<Relationship\b[^>]*/>", ...):
    a = dict(re.findall(r'([\w:]+)="([^"]*)"', tag))
    if "Id" in a and "Target" in a:
        relmap[a["Id"]] = a["Target"]

xml_of = {}                                    # sheet 名 → xml 路径
for tag in re.findall(r"<sheet\b[^>]*/>", ...):
    a = dict(re.findall(r'([\w:]+)="([^"]*)"', tag))
    m = re.search(r"worksheets/(sheet\d+\.xml)", relmap.get(a.get("r:id", ""), ""))
    if m:
        xml_of[a["name"]] = "xl/worksheets/" + m.group(1)
```

> ⚠️ **踩过的坑**：别用"属性顺序"去解析 XML 标签！
> openpyxl 写关系文件时属性顺序是 `Type → Target → Id`，但别的工具可能写成 `Id → Type → Target`。
> 所以**必须先把属性解析成字典**，再按键取，不能靠正则里固定的位置。

### 4.2 `_parse_cols()`：把 `<cols>` 摊平成字典

```python
def _parse_cols(xml):
    m = re.search(r"<cols>.*?</cols>", xml, re.S)
    ...
    for tag in re.findall(r"<col\b[^>]*?/>", m.group(0)):
        a = dict(re.findall(r'([\w:]+)="([^"]*)"', tag))
        lo, hi = int(a.pop("min")), int(a.pop("max"))
        for c in range(lo, hi + 1):
            attrs[c] = dict(a)
    return attrs
```

XML 里 `<col>` 是**按区间**写的（`min="13" max="24"` 表示 13~24 列共享同一套属性），
但改的时候要按**单列**思考，所以这里把它展开成 `{13:{...}, 14:{...}, ..., 24:{...}}`。

**为什么要保留全部属性？** 因为模板里有些列除了分组，还有**列宽**（`width`）、**自定义列宽**（`customWidth`）、**样式**（`style`）。
如果解析时只挑 `hidden/outlineLevel` 三个属性，拼回去就会把这 297 列全搞成默认宽度——**表面上看就是"表格列宽全乱了"**。

> ⚠️ **踩过的坑**：`_parse_cols` 必须**原样保留**模板的默认分组属性；
> `_build_cols` 也只覆盖 `state` 里**显式指定**的列。否则会误清模板里其它无关的分组
> （比如欧洲表尾部「比利时2026年总销量」那一块本来就有自己的分组）。

### 4.3 `_build_cols()`：改完再拼回去

```python
def _build_cols(attrs, state):
    def attr_of(c):
        a = dict(attrs.get(c, {}))
        if c in state:                       # ← 只改 state 里点名要改的列
            st = state[c]
            for k in ("hidden", "collapsed"):
                if st.get(k): a[k] = "1"
                else: a.pop(k, None)         # ← 没指定就删掉这个属性（= 恢复默认）
            if st.get("outlineLevel"):
                a["outlineLevel"] = str(st["outlineLevel"])
            else: a.pop("outlineLevel", None)
        return a
```

**核心是"只动点名要动的列"**。`state` 字典由主函数填，形如：

```python
state[13] = {"outlineLevel": 1, "hidden": True}   # 第 13 列折叠
state[25] = {"collapsed": True}                   # 第 25 列显示 + 按钮
state[80] = {}                                     # 第 80 列恢复不分组
```

拼 XML 时做了一件事：**相邻同属性的列合并**（1029-1040 行）。

```python
out, run0, run_attr, prev = [], None, None, None
for c in sorted(attrs):
    a = attr_of(c)
    if run0 is None:
        run0, run_attr = c, a
    elif a != run_attr or c != prev + 1:      # 属性变了 或 列号断了 → 上一段收尾
        out.append(tag(run0, prev, run_attr))
        run0, run_attr = c, a
    prev = c
```

因为 XML 习惯写成 `<col min="13" max="24" .../>` 而不是写 12 个 `<col>`。
这样拼出来的 XML **和 Excel 自己存的格式一致**，文件不虚胖。

**属性顺序**（第 988 行）也讲究：

```python
COL_ATTR_ORDER = ["style", "width", "customWidth", "hidden", "outlineLevel", "collapsed"]
```

按这个顺序写，其余未知属性用 `sorted()` 兜在后面——保证输出稳定，同一份数据跑两次**字节完全一致**（这是"幂等"的基础）。

### 4.4 `_month_blocks()` / `_eu_month_blocks()`：识别"月块"

两张表的列布局**完全不同**，所以要用不同办法找"哪几列是 1 月、哪几列是 2 月"。

**【2026年】sheet** —— 第 2 行是 `1月 2月 ... 12月` 逐列标签，且每个分组块首尾相连（第 987 行的逻辑）：

```python
def _month_blocks(ws, maxc):
    blocks, run = [], []
    for c in range(1, maxc + 1):
        if not re.fullmatch(r"\d{1,2}月", str(ws.cell(2, c).value or "").strip()):
            continue                          # 不是"X月"就跳过
        if run and c != run[-1] + 1:          # 列号断了 → 上一块结束
            blocks.append(run); run = []
        run.append(c)
        if len(run) == 12:                    # 凑齐 12 个月 = 一个分组块
            blocks.append(run); run = []
    ...
```

**欧洲表** —— 第 2 行的月份标签**只打在"月合计列"上**（而且是个公式 `='2026年'!$B$1&"8月"`），
所以不能直接找 12 列，而是**先找到合计列，再往左推 11 列**（1079-1090 行）：

```python
def _eu_month_blocks(ws, maxc):
    totals = []
    for c in range(1, maxc + 1):
        s = str(ws.cell(2, c).value or "")
        m = re.search(r'"(\d{1,2})月"', s) or re.fullmatch(r"(\d{1,2})月", s.strip())
        if m:
            totals.append((c, int(m.group(1))))
    if len(totals) < 2:
        return totals, 11
    return totals, totals[1][0] - totals[0][0]     # ← 块宽 = 两块间距（=11）
```

**块宽不写死 11，而是用"两块之间的距离"算出来**——这样就算以后国家数变了（比如加一个国家变成 12 列），代码也能自适应。

**主表的规则（1134-1148 行）——"当月及以前平铺，未来的折叠"：**

```python
blocks = [b for b in _month_blocks(ws, maxc)         # 只认完整的 12 月块
          if len(b) == 12 and [str(ws.cell(2, c).value).strip() for c in b]
```

翻译成人话（假设当月 = 8）：

**欧洲表的规则（1149-1176 行）——"过去只留合计列，当月展开，未来整块隐藏"：**

```python

    first = c - width + 1                             # 该月块的起始列
    if m < month_offset:                              # 过去的月
        for cc in range(first, c):
            state[cc] = {"outlineLevel": 1, "hidden": True}   # 明细列折叠
        state[c] = {"collapsed": True}                        # 只留合计列可见

        state[c] = {}

            state[cc] = {"outlineLevel": 1, "hidden": True}
        state[c] = {"outlineLevel": 1, "hidden": True, "collapsed": True}   # 整块隐藏
```

> ⚠️ **踩过的坑**：`elif m == month_offset` 分支里，明细列给的是 `{"outlineLevel": 1}`——**有分组、但没有 `hidden`**。
> 这就是"展开但保留 `+/-` 按钮"的状态。如果把 `hidden` 写成 `False` 而不是"不写这个键"，
> 输出会变成 `hidden="0"`，Excel 虽然认，但和原生格式不一致，可能影响其他工具读取。

### 4.6 `_replace_file()`：处理"文件被占用"

```python
def _replace_file(tmp, dst):
    try:
        os.replace(tmp, dst)          # 原子替换（Windows 上也能覆盖）
        return "replace"
    except PermissionError:           # ← 成品被 WPS/预览器打开时，Windows 拒绝删除+改名
        with open(tmp, "rb") as f:
            data = f.read()
        with open(dst, "wb") as f:
            f.write(data)             # 退化为"原地覆写"
        os.remove(tmp)
        print("    ⚠️ 成品被其他程序占用，已退化为原地覆写（建议关掉 WPS/预览后重跑）")
        return "overwrite"
```

> ⚠️ **踩过的坑**：Windows 上如果文件被别的程序打开着，`os.replace` 会抛 `WinError 5`（拒绝访问）。
> 所以做了降级：**原地覆写**——虽然不如原子替换安全（覆写到一半崩了会坏文件），
> 但至少不会让脚本直接失败。这也是脚本末尾 `os.startfile()` 会自动打开成品带来的副作用。

## 五、为什么这段代码要写成这样（设计取舍）

### 5.1 为什么不用 `=SUM()` 之类的公式？

因为 openpyxl 写公式时**不带计算结果缓存**，写出来的公式在 Excel 里要重新算一遍才显示值。
而这段代码处理的是**列属性**（不是单元格值），完全不需要公式。

### 5.2 为什么坚持"幂等"？

**幂等 = 同一份输入跑 N 次，结果完全一样。**

这是这段代码最看重的性质，原因有两个：
1. 脚本可能因为文件占用等原因被重跑，如果每次跑都"再折一层"，表格就乱了；
2. 出问题时可以放心重跑验证。

**验证方法**：连跑两遍，比对两次产物的字节（md5 一致）。

### 5.3 为什么列号全用 `get_column_letter()` 算，不写死？

```python
from openpyxl.utils import get_column_letter
...
f'横滚到 {get_column_letter(left_col)}'
```

因为 297 列里，手算"欧洲 8 月是第几列"极易出错（实际是 J 列 = 第 10 列，
而"欧洲 5 月"是 G 列 = 第 7 列，差 3 个字母但差 3 列，眼睛容易看串）。
**用函数算，人只需要记住"8 月 = 块首列 + 7"这个规则。**

| 这几百行是 VBA 宏吗？ | **不是，是纯 Python**。零 VBA、零 COM、零 Excel 自动化。 |
