## 3. 第 2 步：逐份算「SKU × 数量」

### 3.1 先认清：三平台的关键列完全不同

| 平台 | SKU 列 | 数量列 | 状态列 | 拆国家/站点用 |
|---|---|---|---|---|
| **Shopee**（菲／跨境马来／跨境新加坡） | `SKU Reference No.` | `Quantity` | `Order Status` | `Country` |
| **Shopee · 泰国** | `เลขอ้างอิง SKU (SKU Reference No.)` | `จำนวน` | `สถานะการสั่งซื้อ` | `ประเทศ` |
| **Shopee · 印尼** | `Nomor Referensi SKU` | `Jumlah` | `Status Pesanan` | — |
| **Shopee · 跨境越南** | `商品规格货号` | `数量` | `订单状态` | — |
| **Lazada** | `sellerSku` | ⚠️ **没有数量列** | `status` | 靠文件名区分站点 |
| **Tiktok** | `Seller SKU` | `Quantity` | `Order Status` | `Country` |
| **KSON 线下** | `SKU` | `数量` | 无状态列（全计） | — |
| **印尼海外仓** | `商品编码\nGoods No` | `商品数量\nQuantity` | `订单状态\nStatus` | 看 `订单号\nOrder No.` 前缀 |

**三个必须记住的坑**：

1. **Lazada 报告一行 = 一件商品**（没有数量列，脚本里写死 `数量 = 1`）。所以 Lazada 是**数行数**，
   不是"对某一列求和"。筛后剩 755 行 → 就是 755 件。
2. **同样是 Shopee，四个站有四种表头语言**：菲/跨境马/跨境新是英语、泰国是泰语、印尼是印尼语、
   跨境越南是中文。别指望"Shopee 就是 `SKU Reference No.`"。
3. **印尼 Shopee 有一个 `SKU Induk`（= Parent SKU，父商品）**，别用它 —— 要用 `Nomor Referensi SKU`。

Tiktok 那两份是 **CSV**：直接双击打开会中文乱码，用「数据 → 从文本/CSV」导入并选 **UTF-8**。

### 3.3 关键转折：**不要**"一份报告做一次透视"

> ⚠️ **这是最容易卡死的地方。** 一份报告做一次透视，你会得到 17 张互相独立的小表，
> 每张表的 SKU 列表都不一样，**手工没法把它们拼成一张宽表**。
>
> 正确做法是**反过来**：先把 17 份报告**堆成一张"长表"**，最后**只做一次透视**。

**① 新建 sheet 命名 `明细`，只留 3 列**（表头一字不差）：

| 列 | A | B | C |
|---|---|---|---|
| 表头 | `SKU` | `数量` | `渠道` |

**② 每份报告：按 3.2 筛完状态后，把 SKU 列和数量列整列复制到 `明细` 末尾，再填「渠道」列。**

- **只复制两列**（SKU / 数量），其余那几十列一概不要——各平台列名不一样，堆进同一张表只会打架。
- 「渠道」列：在该批数据的**第一行**填上渠道名 → **双击填充柄**一次填满该批全部行。
- **Lazada 报告没有数量列**（一行 = 一件）→ 「数量」列整批填 `1`。
- 印尼海外仓报告：SKU 列 = `商品编码\nGoods No`，数量列 = `商品数量\nQuantity`
  （⚠️ **不是** `商品总数量\nTotal Quantity`，那是订单级的）。
- KSON 线下报告：SKU 列 = `SKU`，数量列 = `数量`。

## 4. 第 3 步：做**一次**透视 → 「渠道 × SKU」中间表

`明细` 建好后，这一步只剩 9 个动作：

1. 点中 `明细` 表里**任意一个单元格**
2. 菜单「插入」→「数据透视表」
3. 弹窗里：数据区域应自动框住整张表 —— **核对列一定包含 A:C 三列**；
   放置位置选 **「新工作表」**
   （⚠️ **不要**放回 `明细` / `orders` 这些有源数据的表，否则透视会压在源数据上、
   数据一多就互相干扰）
4. 右侧字段面板：
   - `SKU` → 拖到 **「行」**
   - `渠道` → 拖到 **「列」**
   - `数量` → 拖到 **「值」**
5. 值区很可能默认成了 **「计数」**：双击值区那个字段 →「值字段设置」→ 勾 **「求和」** → 确定。
   （核对：右下角总计应 = `明细` 表 `数量` 列的合计）
6. 「设计」→「报表布局」→ **「以表格形式显示」**
7. 「设计」→「分类汇总」→ **「不显示分类汇总」**

做完应该是：**第 1 列 SKU，后面一列一个渠道，右下角是总计** —— 这就是中间表。

8. **固定成值**（否则一刷新列序就乱）：
   全选透视结果 → 复制 → 右键 → 选择性粘贴 → **「值和数字格式」**
9. **空单元格补 0**：选中整片数据区 → `Ctrl+G` →「定位条件」→「空值」→ 确定
   → **直接敲 `0` → 按 `Ctrl+Enter`**（一次性把所有"该渠道没卖"的空格填成 0，**别手工一格格补**）

最后**按模板的渠道顺序把列拖好、列头改成渠道名**，另存为 `_中间表`
（在主表工作簿里新建辅助 sheet，交付前删掉）。

### 4.1 备选做法：不做透视，**直接 SUMIFS**（更省事、更不容易错）

如果你最终只是要把数填进 10 个 sheet，可以跳过中间表 —— `明细` 建好后，
**直接在每个 sheet 的 8 月渠道列写 SUMIFS**：

```
=SUMIFS(明细!$B:$B, 明细!$A:$A, $A3, 明细!$C:$C, "菲仓shopee")
```

- `$A3` = 本行的 SKU（A 列）；最后一段 = 渠道名（照 3.3 的表抄）
- **好处**：不用管中间表、不用管透视刷新、列顺序天然就是模板顺序；明细补数据后单元格自动更新
- **代价**：它只覆盖"模板 A 列已有的 SKU" —— **明细里有量、但模板 A 列缺行的 SKU 仍会漏掉**，
  所以 §5.2 第 6 点的**补行位**还是必须做

### 4.2 透视表 / 明细表 排错

| 症状 | 原因 | 处理 |
|---|---|---|
| 同一个 SKU 在透视里出现**两行**，数量被拆开 | 两批数据的 SKU 文本**看着一样但不相等**（尾随空格、不间断空格 `\xa0`、全角/半角混用） | 明细表加辅助列 `=IF(LEN(A2)<>LEN(TRIM(CLEAN(A2))),"脏","")` 筛出脏行洗一遍；或按 `=LEN(A2)` 排序，同一 SKU 长度不一致的就是它 |
| 值显示的是"个数"不是"合计" | 值字段默认「计数」 | 双击值字段 → 值字段设置 → **求和** |
| 渠道列缺列 / 数量对不上 | 「渠道」列写法不统一（`菲仓shopee` vs `菲仓 Shopee`） | 「数据」→「删除重复项」看有几种写法 → 统一 |
| 刷新后列顺序乱跑 | 透视的列按排序规则自动排 | 复制 → 选择性粘贴为**值** → 再手工排序 |
| 透视把源数据挤到一边 / 越算越多 | 放置位置选成了「现有工作表」且落在源数据下方 | 重建时选「新工作表」 |
| 空单元格显示空白而不是 0 | 透视默认不显示无数据项 | `Ctrl+G` 定位空值 → 输入 `0` → `Ctrl+Enter` |

### 4.4 🔑 长表 vs 宽表：为什么不能写 `=XLOOKUP(...,"中山仓")`

> 这是手工做最容易卡住的地方，单独说清楚。

**`XLOOKUP` 的第 3 个参数必须是一个"整列区域"**，不能在里面写条件 ——
`Sheet1!B:B="中山仓"` 这种写法**在 `XLOOKUP` / `VLOOKUP` 里是语法错误**
（`SUMIFS` 才有条件参数，见下）。

所以摆在面前只有两条路：

| | 做法 | 公式 | 适用 |
|---|---|---|---|
| **路 A** | 把长表**变形**成宽表（一列一个渠道），再用 `XLOOKUP` | `=IFERROR(XLOOKUP($A3,_中间表!$A:$A,_中间表!B:B,0),0)` | 想按 §4 做透视、或已拿到宽表 |

**路 B 的写法**（直接对着 `se_a_sku_sale_df.csv` 写，4 个条件同时成立）：

## 8. 六个最容易翻车的点

## 9. 手工做不了的三件事（务必知道）

这三样脚本里专门写了代码，**手工做必然出问题**，只能接受或找脚本：

1. **状态过滤口径**——三平台方向相反，人眼筛状态每月都可能漏/多算几十件，而且**不报错**。
   本项目真实事故：Shopee「退货窗口期」状态有"带日期长文本 / 裸状态"两种形态，
   旧代码只做前缀匹配 → **菲丢 102 件、泰丢 204 件、印尼丢 53 件**；
   另有一次是状态归一化的目标值写成了别的站的写法，`.map()` 查不到 → 整批变空、**静默清零**。
2. **跨列重复计数**——119 那种"同一个数落在两列"，人眼几乎发现不了，只能靠 §7 的恒等式对撞。
   所以 **§7 一步都不能省**，否则等于闭着眼睛交数。
3. **打开体验保真**——sheet1 的 **11 条条件格式 + 8 条迷你图**、WPS 的「阅读模式」黄色十字开关、
   列分组展开到当月、冻结窗格定位。这些**只要用 Excel/WPS 另存一次就会丢**，手工保不住。

**结论**：能用脚本就用脚本（改 3 行参数、跑约 40 秒）。手工只用于应急，
且**至少保留 §7 的自检**。为降低风险，建议**两个人分工 + 交叉核对**：
一人算中间表，一人负责填表与自检。
