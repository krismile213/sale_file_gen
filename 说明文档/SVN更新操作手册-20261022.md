## 三、标准提交流程（命令行，在 svn_repo 目录下）

```bash
cd /c/Users/dell/Desktop/work-main/svn_repo
```

### 第 1 步：先更新，避免 out-of-date 被拒

```bash
svn update
```

- 服务器如果有别人的新提交，先合下来。**跳过这步直接 commit，如果服务器版本比本地新会被拒绝**（`svn: E155011` / out of date）。
- 正常情况（没人动过仓库）输出 `At revision 9.` 或 `Updated to revision 9.`，什么都不用做。

### 第 2 步：看本地改了什么

```bash
svn status
```

预期看到 **15 个 `M`（modified）**——就是本次暂存的 15 项（清单见第四节）。
另外可能看到：

- `!` = 文件缺失（不该出现；出现就先查是谁动的）
- `?` = 未版本化的新文件（**不要随手 `svn add`**，先判断该不该进仓库）

### 第 3 步：审查改动内容

```bash
# 代码/文档是文本，可以看 diff
svn diff trunk/month_sale_file.py
svn diff 换月操作手册-全量跑通清单.md

# xlsx 是二进制，svn 只会提示 "Cannot display: file marked as a binary file"，属正常
svn diff trunk/result/数据归属周期/202609/月销售总表.xlsx
```

重点确认三处代码 diff 与 10-16/17 的修改记录对得上：
`month_sale_file.py`（菲律宾新订单报告函数）、`southeast_asia_sale_file.py`（SEA Total 块位 base=15）、
`工具-换月资料体检.py`（KH 表头自愈降级）。

### 第 4 步：删掉误提交的 Office 锁文件垃圾

```bash
svn delete "trunk/result/数据归属周期/202608/~$月销售总表.xlsx"
```

`~$` 开头是 WPS/Excel 的临时锁文件，当初被误提交进仓库（r2/r9），应当清除。
`svn delete` 会同时从磁盘删掉它并在工作副本登记删除，下一步 commit 生效。
（如果磁盘上已经没有了，`svn delete` 对缺失文件同样有效。）

  三处同步（重算目录 / trunk/result / svn_repo）并各自备份。
- **待拍板**：修复会改交付件数据列（值可由恒等式复算），按项目惯例不静默改数——

## 五、坑与注意事项

1. **提交前关掉 WPS/Excel**。`~$` 锁文件就是这么进仓库的；被占用的文件还会导致 commit 失败/读到半截。
2. **提交信息一律 `-F` 文件**，别用 `-m` 传中文（乱码进历史，改不了）。
3. **xlsx 在 SVN 眼里是二进制**：没有行 diff、冲突不能手工合。万一冲突，正确做法是**重新导出/复制正确版本覆盖，再 commit**，别在冲突标记里挣扎。
4. **`svn add` 前三思**：本仓库是「数据 + 结果 + 代码 + 文档」的精选集，不是项目全量镜像（项目里 637 个 trunk 文件，仓库只跟踪 190 个）。
   跑批临时产物、探针脚本、备份目录默认不进仓库；要新增文档（比如本手册）先跟团队打招呼。
5. **`svn update` 遇到冲突**（`C` 状态）：文本文件可编辑解决后 `svn resolve --accept working <文件>`；xlsx 直接 `svn resolve --accept mine-full <文件>` 或用正确版本覆盖后 resolve，然后重新 commit。
6. **中文路径**：仓库里有中文目录/文件名，命令里路径用双引号包住；Git Bash 与 PowerShell 都能跑。
7. **提交后抽查**：`svn log -l 3` 看信息和作者；`svn status` 应干净。
