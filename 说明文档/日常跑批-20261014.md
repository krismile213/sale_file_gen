### 修掉的缺陷：销售报告「改名漂移」

| | 10-13 快照 | 10-14 快照 |
|---|---|---|
| 欧盟簿销售报告文件名 | 亚马逊**欧洲**站点202610订单报告.txt | 亚马逊**欧盟**站点202610订单报告.txt |

runner 原先对销售报告只按**单一文件名**查找（库存报告支持候选列表、销售报告不支持）→ 名字一变就找不到，**欧盟簿的每日销售 append 会被静默跳过**（只在日志留一行 `[缺报告] 销售`，不报错、不中断）。

**修复**（通用化，以后任何报告改名都能兜住）：
- `pipeline/core/config.py`：欧盟簿 `sales.report` 改为候选列表 `["亚马逊欧洲站点…", "亚马逊欧盟站点…"]`。
- `pipeline/core/runner.py`：销售报告解析与库存报告对齐——`report` 可为列表，按顺序取第一个存在的。

## 四、你以后人工跑代码

**一条命令**（在 `Daily_Sales_Report` 目录下，任意位置皆可）：
```
python pipeline/run.py
```
默认自动取**最新**快照目录（`trunk\data\数据归属周期\202610\快照日期\YYYYMMDD`），数据日取该目录名。

常用参数：
```
python pipeline/run.py --dry-run           # 只看计划，不写文件（跑前建议先来一遍）
python pipeline/run.py --snap <目录>        # 指定快照
python pipeline/run.py --only 日本,欧盟      # 只跑文件名含关键字的簿
python pipeline/run.py --jobs 1            # 串行、日志按顺序（排查问题用）
```

**跑前**：关掉 WPS/Excel（否则该簿被占用会整份丢弃）。
**跑后**：看日志有没有 `[缺报告]` / `[!]` / `未命中`（结余式表那行「未命中0行」是正常输出，不是问题）。
