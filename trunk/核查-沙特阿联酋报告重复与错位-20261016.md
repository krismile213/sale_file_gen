## 二、⚠️ pipeline 风险：别把 interflow"沙特"加进 group 列表

`trunk/month_sale_file.py`：

```python
L1441  interflow_sale_groups = ["北美", "澳大利亚", "阿拉伯联合酋长国"]   # 不含沙特
L193   order_df["站点"] = order_df["sales-channel"].map(channel_country_map)
```

- 国家归属走 **sales-channel 映射**，不靠文件名。所以合并报告里的 50 条 `Amazon.ae` 会判成阿联酋、
  1 条 `Amazon.sa` 判成沙特（这点是对的）。
- **但如果把"沙特"加进 interflow groups**：阿联酋文件与沙特文件内容相同 ⇒ 50 条 AE 订单被读两遍
  ⇒ **阿联酋销量翻倍**。除非拿到真正的"沙特-only"报告，否则不要加。
- `工具-换月资料体检.py` L98-99 也确认：interflow 只期望 北美 / 澳大利亚 / 阿拉伯联合酋长国。

## 五、归类统计核查：日销表 vs 月销表（2026-10-16 补）

### 日销表（Daily_Sales_Report）——❌ 阿联酋簿已被污染

取数逻辑：`core/config.py` 每簿用 `sales=dict(report="…")` 指定**单一报告文件**；
`runner.append_sales`（L767）**整份灌入、不按 sales-channel 过滤**，只做 order-item-id 去重。
⇒ 国家归属完全取决于"哪个文件喂给哪个簿"。

| 工作簿 | 取数文件 | 结果 |
|---|---|---|
| 沙特库存销售表.xlsx | 亚马逊沙特阿拉伯站点{m}订单报告.txt | ✅ 干净（1161 条全 Amazon.sa） |
| **阿联酋库存销售表.xlsx** | 亚马逊阿拉伯联合酋长国站点{m}订单报告.txt | ❌ **混入 623 条 Amazon.sa** |
| Interflowd阿联酋库存销售表.xlsx | interflow阿拉伯联合酋长国站点{m}订单报告.txt | ⚠️ 含 1 条 Amazon.sa |

**实测冗余（阿联酋库存销售表.xlsx / 每日销售数据阿联酋）**

- 渠道分布：`Amazon.ae` 773 ｜ **`Amazon.sa` 623** ｜ Non-Amazon 4
- 这 623 条 SA 订单日期覆盖 **09-30 ~ 10-13**，与 `沙特库存销售表.xlsx` 中的订单
  **623/623 完全重复**（同一批沙特单被两本簿各存一份）。
- ⚠️ **更正（10-16 复核）**：先前"这 538 件会进入 `阿联酋-每日库存分析表` 销量统计 → 日销虚高"
  的判断**是错的**。分析表日列公式带**渠道过滤**：

  ```
  =SUMIFS(每日销售数据阿联酋!$O:$O, …!$L:$L,$A7, …!$AE:$AE,Y$5, …!$G:$G,$D$5, …!$AF:$AF,$D$4)
  ```

  其中 `$D$5 = "Amazon.ae"`、`$D$4 = 1`（有效性）⇒ **SA 行恒不满足条件、贡献 0**。
  实证：跑批日志 `[月汇总] 阿联酋-每日库存分析表: 2026-10 … 504 件`，
  与实测"AE 渠道 10 月合计 504 件"完全吻合。该簿亦**无透视部件**（`xl/pivot*` 为空）。
  ⇒ **分析表 / 月汇总 / 任何计算输出均未受影响，异国行只是原始行冗余。**

| 日期 | SA 冗余行/件 | | 日期 | SA 冗余行/件 |
|---|---|---|---|---|
| 09-30 | 5 / 4 | | 10-07 | 42 / 41 |
| 10-01 | 34 / 31 | | 10-08 | 45 / 39 |
| 10-02 | 32 / 29 | | 10-09 | 63 / 59 |
| 10-03 | 47 / 41 | | 10-10 | 52 / 50 |
| 10-04 | 55 / 49 | | 10-11 | 55 / 45 |
| 10-05 | 49 / 40 | | 10-12 | 50 / 48 |
| 10-06 | 50 / 47 | | 10-13 | 16 / 15 |

（上表仅为"若渠道过滤失效时的潜在影响"，当前口径下**不计入**。）

- **来源**：20261013 快照的"亚马逊阿联酋订单报告"实为沙特数据。日销线在 10-13 那次 run 把
  整份（月累计）灌进阿联酋簿；后续 run 只追加不删除 ⇒ 行留存。
- 日销线**无合计簿**（12 本各自独立），双计局限在"阿联酋簿多存一份沙特原始行"。
- **20261016 快照的"亚马逊阿联酋订单报告"已修正**（554 `Amazon.ae` + 3 Non-Amazon，无 SA），
  10-16 重跑**未新增污染**。

### 月销表（trunk/month_sale_file.py）——✅ 逻辑正确，但有快照依赖风险

- 国家归属走 **sales-channel 映射**（L193 `order_df["站点"] = …map(channel_country_map)`），
  不靠文件名 ⇒ 合并报告能自动拆分，逻辑正确。
- `interflow_sale_groups`（L1441）**不含沙特** ⇒ 不会读那份冗余的 interflow 沙特文件 ⇒ 不会重复。
- ⚠️ 若**用 20261013 快照跑**：巨川"阿联酋"文件=沙特数据 → 站点被判成沙特阿拉伯
  ⇒ **沙特双计（617+623≈1240）、阿联酋=0**。用 14/15/16 快照则正常。
- 现状：`trunk/sale_file_tmp/*` 是 10/09 的旧产物（202610 月销尚未跑），成品未受影响。

### 处置建议

1. **治本**：日销线给 `append_sales` 加**期望渠道校验**（config 每簿加 `expect_channel`，
   如 `Amazon.sa` / `Amazon.ae`），不匹配的行拒收并告警。
2. **清洗（可选，优先级低）**：`阿联酋库存销售表.xlsx` 删除那 623 条 `Amazon.sa` 行（先备份，走保真保存管线）；
   `Interflowd阿联酋库存销售表.xlsx` 的那 1 条 SA 行同理（或给 interflow 建独立沙特簿）。
   —— 因分析表按渠道过滤且该簿无透视，**删除与否不影响任何产出**，纯属数据卫生。
3. **月销线**：确保 202610 用 20261016 快照（或 14+）跑；换月体检加"两国报告 md5 / SKU 集合比对"。
